> 构建日期：2026-10-12 ｜ 数据源：22 校/单位 3179 位导师的**官方页面自述** + **论文署名记录**

## 一、这张图是怎么做的（与"纯署名反推"的区别）

最初的做法是「共同署名反推」——统计谁和谁经常一起发论文。这个方法有两个硬伤：**两位平级教授合作会被误判成师徒**，而且**看不出海外师承**。

现改为**以本人页面的自述为起点**，逐人抽取：

| 抽取内容 | 正则目标 | 样例（页面原文） |
|:--|:--|:--|
| **师承** | `导师为/师从 XX` | 李赛：*"博士导师为**赵巍胜**教授、诺奖得主费尔教授"* |
| **学历** | `XXXX年毕业于 XX` | 伍连博：*"2012年本科毕业于**中国科学技术大学**；2020年博士毕业于**瑞士苏黎世联邦理工学院**"* |
| **博士后** | `XXXX-XXXX 在 XX 从事博士后` | 伍连博：*"2020-2021年在ETH从事博士后研究，**合作导师为 Taekwang Jang 教授**"* |
| **课题组名单** | `XX导师：A、B、C` | 朱樟明：*"杭州全职导师：钱利波、刘贝、陈力生…"* |

**覆盖情况**：扫描 3206 份导师页面 →
- 380 份抽到**学历**信息（含具体毕业院校）
- 121 份抽到**师承**提及（180 条）
- 62 份抽到**博士后**经历

## 二、四个证据等级（图中以颜色区分）

| 等级 | 颜色 | 判定依据 | 条数 |
|:--|:--|:--|--:|
| **L1 自述师承** | 亮金黄（粗） | 本人页面**明写**「导师为／师从 XX」 | **27** |
| **L2 交叉证据** | 橙（中） | 页面自述**毕业院校** ＋ 该院校教授在其**早期论文中固定为末位作者**（两条独立证据交叉） | **6** |
| **L3 署名推断** | 暗黄（细） | 仅有「早期一作 ＋ 固定末位作者」署名模式，**无学历佐证** | **260** |
| **L4 合作** | 蓝色（虚线） | 共同署名 ≥3 篇（**仅作背景，不主张师承**） | **4885** |
| 同门 | 绿色（点线） | 由 L1–L3 师徒边派生的"同一导师"关系 | 402 |

**关系判定的三道关卡**（每一道都会丢弃数据）：

1. **姓名 + 机构双重校验** — Crossref 里同名极多。测试中「Chao Wang」在库内有 3 位候选，若论文机构是 Beihang 而候选者在华科/东南/清华，**直接丢弃**，绝不将就。本轮因此拒绝 56621 次匹配。
2. **方向判定** — 学生 = 早期论文**第一作者**；导师 = 同一论文**末位作者**。这是中文学术界最稳定的模式。
3. **时间窗口** — 论文必须落在该人的**学生生涯期**（毕业年 ±7 年，或本人发表记录前 6 年）。这一步专门用来排除"两位教授近年合作"被误判为师承。

## 六、使用方式

### 交互页面（推荐）

**[导师关系网络.html](导师关系网络.html)** — 单文件，离线可用

**四轮迭代的取舍**（记下来避免重蹈覆辙）：

| 版本 | 做法 | 结果 |
|:--|:--|:--|
| v1-v3 | 把 400-2200 个节点同时铺在画布上（力导向 / 树状 / 按院校分区） | 无论怎么排都杂乱 |
| v4 | 改成纯文字大纲 | 不乱了，但**失去了直观** |
| **v5** | **图形保留，但默认只画关键节点，点击才展开子树** | 干净且直观 |

数据依据：165 位导师有学生，但只有 **20 位有 ≥3 名学生**。默认只画这 20 个，
画面极干净；点开一位，他的完整师承树独占画布。

三个视图：
- **师承树**（默认）：总览 20 位导师（圆大小＝学生数，粉圈＝有跨校学生）；
  点击任意导师 → 展开其师承树（学生自动换行，每行最多 8 个）；顶栏「返回总览」
- **放射聚焦**：以某人为中心，内环学生、外环导师、再外同门与合作者
- **合作热力图**：22×22 院校矩阵，4885 条合作压成 484 格

侧栏阈值滑块可调整「显示学生数 ≥ N 的导师」（1 → 165 位，3 → 20 位，8 → 4 位）。

## 七、局限（必须说明）

1. **覆盖有限**：3206 份页面中仅 **121 份**提到导师。多数中文教师主页只写学历不写导师。因此 L1 只有 27 条——这是**"没找到"而非"不存在"**。
2. **L3 可靠性明显低于 L1/L2**：260 条 L3 边仅有署名模式支撑。虽然已加时间窗口约束，仍可能存在"资深教授与年轻同事合作"被误判的情况。**建议以 L1/L2 为准。**
3. **课题组名单抽取有限**：`杭州全职导师：A、B、C` 这类名单只抽到少量，且需人工判断是"同组"还是"我指导的人"。
4. **外部导师有噪声**：107 位中少数是误抽（如"研究助理"这类非人名），已尽量过滤但未穷尽。
5. **学历年份部分缺失**：380 份学历记录中约 4 成的年份为 null（页面只写学校不写年份）。

## 八、复现

```bash
node tools/extract_cv.mjs        # ① 从 3206 份页面抽取学历/师承/博士后
node tools/cv_lineage.mjs        # ② 师承名匹配库内导师（L1）
node tools/build_network.mjs     # ③ 从论文署名建共同作者网络（含姓名+机构双校验）
node tools/finalize_network.mjs  # ④ 署名模式推断师承（L3）
node tools/cv_paper_lineage.mjs  # ⑤ 学历×论文交叉证据（L2）
node tools/merge_network.mjs     # ⑥ 合并四个等级 → network_final.json
node tools/net_html.mjs          # ⑦ 生成交互页面
python tools/net_preview.py      # ⑧ 生成静态图
```

**校验**：`node tools/exec_net_html.mjs`（用桩件真实执行页面脚本，抓运行时错误）、`node tools/lint_html_js.mjs`。
