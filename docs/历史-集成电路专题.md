## 🔍 关键方法：为什么用「论文池反向匹配」

**问题**：中文拼音重名极严重。按人名去 Crossref 检索时，常见名（如「刘明」「王磊」「Xiao Wang」）
会被大量同名者挤占相关性排序，本人论文即使存在也排在数百条之外——早期版本因此有 606 位导师显示为「零论文」，
其中包含院士与资深教授，明显是召回失败而非真的没有产出。

**做法**：反转检索方向。

1. 按 **44 本 IC 相关期刊的 ISSN**（JSSC / TCAS-I/II / TVLSI / TCAD / TED / EDL / MTT / TPEL /
   Nature Electronics / APL / Optics Express / PRL / ACS Nano 等）用 Crossref 游标深分页**全量抓取**
   2008 年至今的论文（约 **96 万篇**）；
2. 对每篇论文的**每一位作者**，用「姓名精确匹配（去空格小写归一）+ **该作者本人的机构字段**校验」回查名录；
3. 因为不经过相关性排序，同名者的干扰被彻底绕开，匹配完全由「姓名 + 机构」两个硬条件决定。

**效果**：可核实论文的导师从 2584 人提升到 **3014 人（94.5%）**，
零论文记录从 606 人降到 **176 人**，S 级产出者从 390 人增至 **544 人**。

> **机构匹配为什么不能只写校名**：大量论文的作者机构串只写实验室名而不写校名——
> 西电「智能感知与图像理解重点实验室」、成电「电子薄膜与集成器件国家重点实验室」、
> 北大「介观物理国家重点实验室」、南大「固体微结构国家实验室」、华科「强电磁工程与新技术国家重点实验室」…
> 若正则只匹配校名，这些论文会**被静默漏收**。因此各校的匹配规则里都并列了
> 校名 + 重点实验室名 + 学院英文名。同理，Crossref 的机构串还常带 HTML 实体
> （`Xi&#x2019;an Jiaotong University`），必须先解码再匹配。
> 这两条是召回率的关键，新增学校时务必先跑 `tools/probe_aff.mjs` 看真实写法。

**质量保障**：采集完成后有独立的产出侧校验（`tools/validate_pool.mjs`），
逐条重新核验「被匹配作者的机构是否真的属于该校」，不通过即剔除——当前剔除率 0.1%，
且高产学者的机构一致率约 99%。

> 已知取舍：论文若挂在其**前单位**（如入职前在海外高校），因机构不符会被排除，
> 因此本库反映的是**在本机构期间的公开产出**，不等于学者的完整学术生涯。

> 踩坑记录：采集脚本曾把 `SCHOOL_META` 的字段名 `include` / `exclude` 误写成 `src.inc` / `src.exc`，
> 导致 `new RegExp(undefined)` 匹配一切、机构校验静默失效（81.7% 匹配失真）。
> 这正是「产出侧校验」存在的意义——**不要只信任采集过程，要独立复核最终数据。**

## ⚠️ 重要局限（请务必阅读）

1. **同名污染与漏检**：中文拼音重名严重（含**同校内重名**），已做「姓名精确匹配 + 作者本人机构校验 + 非工科期刊剔除 + 特定期刊定向补检」四重处理（剔除 1400+ 篇他人论文、补回 130+ 篇漏检），仍有约 385 位导师未能检索到论文。标记"低置信""疑似漏检"的记录**请以官方主页为准**。
2. **T3/T4 不代表水平低**：常见成因是姓名重名、英文署名与拼音不符（吕 → Lyu/Lu）、研究以中文期刊与工程为主、主页长期未更新。
3. **顶会漏计**：Crossref 对 IEEE 会议论文（尤其 ISSCC/CICC）作者机构字段收录不完整，会**系统性低估**顶会产出；中文期刊（CNKI/万方）完全未覆盖。
4. **"论文数"口径**：指**可核实的 IC 相关论文数**，不含非电子/信息领域的同名论文；页面详情里另给出"全部相关论文数"。
5. **未做逐篇全文质量评分**：论文 PDF 绝大多数在订阅墙内，质量维度基于 venue 层级 + 引用 + 产出结构。
6. **招生信息有时效性**：主页表述可能滞后，以导师回复与院系最新通知为准。
7. **"组内学生数"是下限估计**：由论文一作去重推算，不等于实际在读人数。
8. **已知数据缺口（诚实披露）**：
   - **职称缺失 69 人**（中科院 18、哈工大 33、南大 10、浙大 8）——这些教师的公开页面确实未标注职称，
     我们选择**留空而非猜测**（错误职称会污染头衔评分，比空白更糟）；
   - **部分教师无公开主页**（成电 374、上交 112、天大 50 等），因此无法给出联系方式或招生信息；
   - **176 位教师未检索到任何论文**，其中 115 位在各数据源中确实无记录（多为近年入职或 Crossref 无机构字段），
     61 位的论文发表在材料类期刊（超出本库 IC 口径）；
   - **论文挂前单位者会被排除**（见上文方法说明），故本库反映的是**在本机构期间的公开产出**。
8. **不含指导质量**：导师性格、组会风格、补助、毕业去向、是否允许实习等**文献数据里没有**，必须向在读/毕业学生核实。

## 🛠 复现与扩展

> **关于体积**：整仓工作副本约 71 MB（用 `python tools/repo_size.py` 实测，不要依赖本行数字——它会随数据增长而过期）。其中 `data/processed/mentor_ranked.json`（约 33 MB）保存了每位导师的逐篇论文证据，是核验与二次分析的基础；工作台自带的结构化资料与来源模块快照（`workbench/reference/`、`workbench/tests/fixtures/`，合计约 16 MB）让克隆后无需重新联网采集即可直接运行、并离线跑来源解析测试。
> 只想看结论的话，下载 `reports/` 下的单个 HTML 即可（自包含单文件，200–1500 KB）。
> **关于可移植性**：所有脚本以自身所在目录的上一级作为仓库根目录，不含任何绝对路径，可克隆到任意位置运行。

### 一、数据更新的节奏（当年的口径）

| 时机 | 更新什么 | 原因 |
|:--|:--|:--|
| 每年 9–10 月 | 全量重建（师资名录 + 论文 + 课题组主页） | 新学年开始，师资与招生信息变动最大 |
| 每年 3–4 月 | 只刷新课题组主页 | 招生信息集中在春季发布 |
| 随时 | 收到 Issue 更正时单独修数据并重新生成报告 | 权利人诉求优先（承诺 7 个工作日，见上文「参与贡献」） |

### 二、采集与清洗的铁律

> ① 只抓公开可访问页面；② 请求间隔 ≥300 ms、并发 ≤12；③ **不写邮箱**（`email` 一律 `null`），
> 不编造任何字段。

```bash
node tools/clean_rosters.mjs     # 去邮箱 + 过滤简历片段类垃圾关键词
python tools/prepare_names.py    # 中文姓名 → 英文变体（多音字异读组合）
```

`prepare_names.py` 里的 `SCHOOL_META` 需要为每所学校登记机构匹配规则：

```python
"xx": {
    "school": "XX大学",
    "include": r"xx university|xx univ",          # Crossref 机构串匹配（正则，忽略大小写）
    "exclude": r"xx university of science|other",  # 需要排除的近似机构名
},
```

**这一步最影响召回率**；改完用 `node tools/gaps.mjs` 看各校缺口。

### 三、论文检索的四步走，与两个必须记住的坑

```bash
node tools/enrich_crossref.mjs              # ① 逐人检索：姓名 + 机构联合
node tools/reenrich_low.mjs 2               # ② 补检一：论文数 ≤2 的教授改用纯姓名检索
node tools/reenrich_topic.mjs 2             # ③ 补检二：按 IC 核心期刊 ISSN 定向检索
node tools/harvest_pool_match.mjs           # ④ 论文池反向匹配（方法见上文「关键方法」一节）
node tools/validate_pool.mjs                # ⑤ 产出侧校验：逐条复核机构归属
node tools/merge_pool.mjs                   # ⑥ 合并进各校 enriched 数据（按 DOI 去重）
```

期刊 ISSN 列表有两处，可按需增删：`harvest_pool_match.mjs` 顶部的 `JOURNALS`（全量抓池用）、
`reenrich_topic.mjs` 顶部的 `ISSN`（个体补检用）。

**第 ⑤ 步为什么不能省。** 不要只信任采集过程，要独立复核最终数据。`validate_pool.mjs` 不看采集逻辑，
只逐条重新核验「被匹配作者的机构是否真的属于该校」。它曾抓出一个致命 bug：采集脚本把
`SCHOOL_META` 的字段名 `include`/`exclude` 误写成 `src.inc`/`src.exc`，导致
`new RegExp(undefined)` **匹配一切**、机构校验静默失效（81.7% 的匹配失真）。修复后剔除率 0.1%，
高产学者机构一致率约 99%。

**HTML 实体坑。** Crossref 的机构串里带 HTML 实体（`Xi&#x2019;an Jiaotong University`、
`Science &amp; Technology`），必须先解码再做正则匹配，否则整所学校的召回率会崩掉——西安交大曾因此
只有 31/156。解码函数 `decodeEnt()` 已内置在采集与补检脚本中。

### 四、课题组主页与招生信号

```bash
node tools/fetch_labs_all.mjs    # 抓取全部有主页的导师
node tools/analyze_labs.mjs      # 提取招生原话、课题组名
```

原始文本缓存在 `data/raw/lab_pages/<school_key>_<姓名>.txt`，**已抓过的会自动复用**，重跑很快。

> **文件名用 school_key，不要用中文校名前 4 字**——「清华大学」与「清华大学深圳国际研究生院」前 4 字
> 相同，中科院拆分后 6 个所的前 4 字都是「中国科学」，会互相覆盖。若接手的是旧数据，
> 先跑 `node tools/migrate_labpage_names.mjs` 迁移。

**招生信号的两条防误判判据（务必保留）：**

1. **站点模板过滤**：同一语句若在**同校 ≥4 人**的页面上出现，判定为站点新闻栏/导航模板并剔除。
   中科院微电子所官网的新闻栏（「夏令营报名通知」「拟录取名单公示」）曾让该所 **78/78 人**全部被误标为
   「在招」；加此判据后降为 0/23。
2. **姓名邻近度**：同时记录招生语句与该人姓名的距离（±200 字内为 `near`）。

改完务必用 `node tools/check_recruit_bias.mjs` 看各校在招占比——**若某校接近 100%，几乎一定是模板误判**。

### 五、推荐集与报告生成顺序

```bash
node tools/curate.mjs            # 构建推荐集（聚焦方向 + 其他方向在招）
node tools/html_db.mjs           # 生成全库 HTML
node tools/html_recommend.mjs    # 生成推荐 HTML
node tools/report_final.mjs      # 生成全库排名报告 MD
node tools/report_recommend.mjs  # 生成推荐与招生信息报告 MD
node tools/strip_emails.mjs      # 【必跑】兜底清除任何残留邮箱
python tools/make_docx.py "reports/导师库-详细排名报告.md" "reports/导师库-详细排名报告.docx"
python tools/make_docx.py "reports/导师推荐与招生信息.md" "reports/导师推荐与招生信息.docx"
node tools/verify_html.mjs reports/导师推荐.html reports/导师库.html   # 校验 HTML 数据可解析
```

- `strip_emails.mjs` **必须放最后**：它会清洗**字段名**和**字符串里嵌的邮箱**（例如主页原话
  「请发送简历至〈邮箱〉」），而生成脚本无法预知这些内容。
- **生成器里的统计数字与院校清单不要写死**——已改为从 `mentor_ranked.json` 动态读取；
  新增学校或拆分单位后，报告文案会自动跟随。

### 六、名录结构变动时（新增学校 / 拆分公司）

```bash
node tools/clean_rosters.mjs && python tools/prepare_names.py   # 重新生成姓名变体
node tools/find_dups.mjs            # 检查同校同名（必须为 0，否则下游键会互相覆盖）
python tools/disambig_all.py        # 同校同名消歧（加院系/方向后缀）
python tools/fill_name_en.py        # 外文姓名补 name_en（否则拼音会逐字母拆碎）
node tools/check_roster.mjs data/raw/*/roster_*.json   # 名录结构合规校验
node tools/sync_roster_fields.mjs   # 把名录的身份字段同步回 enriched_*.json
```

**中科院按所拆分**的参考实现见 `tools/split_cas.mjs`：把一个总名录按 `department` 字段拆成多份，
并为每个所单独配置 Crossref 机构匹配规则（避免所间串号）；拆完后须在 `prepare_names.py` 的
`SKIP_KEYS` 中登记原总名录，防止重复登记。

### 七、公开前审计（每次推送前都要跑）

```bash
node tools/audit_prepublish.mjs
```

它检查隐私红线、个人信息与本地路径、硬编码绝对路径、评价性用语、合规文档齐备、数据文件可解析、
相对链接、凭证扫描、提交者身份、统计自洽等。**出现阻塞项就不应推送**。项数以脚本实际输出为准
（本文迁入时实测：`14 通过 / 4 警告 / 0 阻塞`）。

| 检查 | 说明 |
|:--|:--|
| 邮箱残留 | 产物与代码中不得出现任何邮箱（隐私红线） |
| 个人信息 / 本机路径 | 不得出现真实姓名、个人邮箱前缀、主机名、本地目录结构 |
| 硬编码绝对路径 | 脚本须可移植（以脚本位置解析仓库根目录） |
| 评价性用语 | 报告中不得出现"避雷/天坑/不推荐/水平差"等表述 |
| 合规文档齐备 | README / DISCLAIMER / CONTRIBUTING / LICENSE×2 / CITATION / Issue 模板 / CI / 落地页 |
| 数据文件完好 | 全部 JSON 可解析，名录非空且无邮箱值 |
| 相对链接有效 | Markdown 与落地页里的相对链接均可解析 |
| 凭证扫描 | 不得出现 token / 私钥 / 密码 |
| 提交者身份 | 必须全部是 GitHub 匿名邮箱 |
| 统计自洽 | 声明的人数与数据文件一致 |

### 九、常见问题排查（当年真实踩过的坑）

| 现象 | 原因 | 处理 |
|:--|:--|:--|
| 某位知名教授论文数异常少 | 同校同名者挤占了 Crossref 检索结果前 200 条 | 跑 `harvest_pool_match.mjs`（论文池反向匹配）；仍不行用 `reenrich_topic.mjs` 或 `probe_missing.mjs` 单点排查 |
| 某人被计入大量医学/化学论文 | 同名污染 | 已由 `score.mjs` 的非工科期刊过滤；必要时补充 `OFF_FIELD` 词表 |
| 抓取全是乱码 | 目标站点用 GBK / 声明的 charset 是错的 | 解析器已做保守的编码判定（见采集器 `_decode` 的规则）；异常时人工核对原始字节 |
| Crossref 返回 429 | 请求过密 | 降低并发；Crossref 友好池要求带 `mailto` |
| 产物里又出现邮箱 | 生成脚本把主页文本原样带出 | 跑 `strip_emails.mjs`，并检查是否有新字段名未被 `EMAIL_KEY` 覆盖 |
| HTML 打开后表格空白 | 数据 JSON 被破坏 | `verify_html.mjs reports/*.html` 定位 |
| 某所学校整体召回率异常低 | Crossref 机构串含 HTML 实体 | 已内置 `decodeEnt()`；新学校名称含撇号或 `&` 时务必确认解码（西交曾 31/156，修复后 119/156） |
| 改完匹配规则但数据没变化 | `enrich_crossref.mjs` 默认跳过已存在的产物 | 先删对应中间产物再重跑 |
| 脚本报 `'list' object has no attribute 'get'` | 名录目录里有数组格式的中间产物（`roster_draft.json` / `roster_stage.json`）被 glob 误匹配 | 中间产物命名为 `_draft.json` / `_stage.json`，或依赖脚本内置的跳过逻辑 |
| 同校两位同名教师互相覆盖 | 管线按 `学校\|姓名` 建键 | 跑 `disambig_all.py` 加括号后缀消歧（`prepare_names.py` 已支持括号不参与读音） |
| 某校「在招」比例接近 100% | 站点新闻栏模板被当成本人招生表述 | 已内置「同校 ≥4 人重复即剔除」判据；用 `check_recruit_bias.mjs` 复查 |
| 某校论文数明显偏少 | 该校大量论文的机构串只写实验室名（不含校名） | 在该校 include 规则里补上重点实验室名；先用 `probe_aff.mjs` 看真实写法 |
| 主页链接点开是报错 | 原采集源主机已下线 | 跑 `fix_dead_links.mjs` 置空死链；再用 `verify_homepages.mjs` 抽查可达性 |
| 自动补的职称明显不对（如整批出现「院士」） | 页面噪声文本被误当职称 | **错误职称比缺失更糟**（污染头衔评分）。只接受「姓名真实出现 + 职称在姓名前后 40 字窗口内 + 排除导师/招生类表述」的严格匹配，且不自动判定院士 |
| 拉取别人的 clone 后脚本报路径错误 | 旧版脚本含硬编码绝对路径 | 已全部改为以脚本所在目录的上一级解析仓库根目录；若从旧版 fork，需自行替换 |

### 十、入库边界与「克隆即可复现」

公开仓库必须让人**克隆下来就能用**，同时不能把几十 MB 的中间产物也带进去。因此当年的脚本分两类：

| 类别 | 依赖 | 克隆后能否直接跑 | 代表脚本 |
|:--|:--|:--|:--|
| **A 类** | 只读**已入库**产物：`mentor_ranked.json`、`curated.json`、`lab_pages.json`、各校 `roster_*.json` | 能 | `summary` / `check_doc_numbers` / `html_db` / `html_recommend` / `report_final` / `report_recommend` / `list_tiers` / `anomaly_check` / `audit_prepublish` |
| **B 类** | 需要**未入库的中间产物**：`enriched_<key>.json`、`name_variants.json`、`mentor_db.json` | 需先按上文顺序重跑 | `score` / `contamination_scan` / `assess_filter` / `decode_affs` |

B 类脚本在缺文件时**必须给出友好提示并以退出码 0 结束**，不要抛栈。每次推送前跑一遍
`node tools/clone_selftest.mjs`，它会逐个执行 A 类脚本确认可运行，并验证 B 类脚本的缺失提示是否友好。

**一句话验证可复现性**（当年的做法）：

```bash
git clone --depth 1 <仓库地址> /tmp/x && cd /tmp/x
node tools/html_db.mjs && node tools/report_final.mjs
# 产物应与仓库中的 reports/ 完全一致（MD5 相同）
```

### 十一、扩展方向（历史口径）

- **增加学校**：见 [CONTRIBUTING.md](../CONTRIBUTING.md) 第二节（该节目前仍按旧管线撰写）；
- **增加期刊层级**：改 `tools/classify.mjs` 的 venue 分层表（S/A/B）；
