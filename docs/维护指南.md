# 维护指南（面向后续维护者）

> 这份文档写给**接手更新本项目的同学**。数据不是一次性的——每学期都该刷新一次。
> 全流程零成本（只用免费公开 API），单人一天可以跑完全套。

---

## 一、数据更新的节奏建议

| 时机 | 更新什么 | 原因 |
|:--|:--|:--|
| **每年 9–10 月** | 全量重建（师资名录 + 论文 + 课题组主页） | 新学年开始，师资与招生信息变动最大 |
| **每年 3–4 月** | 只刷新课题组主页（第 9–10 步） | 夏令营招生信息集中在春季发布 |
| **随时** | 收到 Issue 更正时，单独修数据并重新生成报告 | 权利人诉求优先，承诺 7 个工作日 |

---

## 二、全量重建流程

### 0. 环境

```bash
node -v      # 需要 ≥18（用到原生 fetch）
python -V    # 需要 ≥3.10
pip install pypinyin python-docx
```

### 1. 更新师资名录

每所学校的名录在 `data/raw/<school_key>/roster_<school_key>.json`。刷新方式二选一：

- **增量检查**：打开 `sources` 字段里的 URL，对比官网人数与本地 `faculty` 长度，补齐新增教师；
- **整校重抓**：参照 [CONTRIBUTING.md](../CONTRIBUTING.md) 第二节的字段规范重抓。

> ⚠️ 采集三条铁律：① 只抓公开可访问页面；② 请求间隔 ≥300 ms、并发 ≤12；
> ③ **不写邮箱**（`email` 一律 `null`），不编造任何字段。

### 2. 清洗与姓名变体

```bash
node tools/clean_rosters.mjs     # 去邮箱 + 过滤简历片段类垃圾关键词
python tools/prepare_names.py    # 生成 name_variants.json（多音字异读组合）
```

`prepare_names.py` 里的 `SCHOOL_META` 需要为每所学校配置：

```python
"xx": {
    "school": "XX大学",
    "include": r"xx university|xx univ",          # Crossref 机构串匹配（正则，忽略大小写）
    "exclude": r"xx university of science|other",  # 需要排除的近似机构名
},
```

**这一步最影响召回率**，改完建议用 `node tools/gaps.mjs` 看各校缺口。

### 3. 论文检索（四步走，缺一不可）

```bash
node tools/enrich_crossref.mjs              # ① 逐人检索：姓名 + 机构联合（约 15 分钟 / 3190 人）
node tools/reenrich_low.mjs 2               # ② 补检一：论文数 ≤2 的教授，改用纯姓名检索
node tools/reenrich_topic.mjs 2             # ③ 补检二：按 IC 核心期刊 ISSN 定向检索
node tools/harvest_pool_match.mjs           # ④ 【关键】论文池反向匹配（约 6 分钟）
node tools/validate_pool.mjs                # ⑤ 产出侧校验：逐条复核机构归属
node tools/merge_pool.mjs                   # ⑥ 合并进各校 enriched 数据（按 DOI 去重）
```

#### 为什么必须做第 ④ 步「论文池反向匹配」

按人名检索时，常见中文名（「刘明」「王磊」「Xiao Wang」）会被大量同名者挤占 Crossref 的
相关性排序，**本人论文即使存在也排在数百条之外**——早期版本因此有 606 位导师（含院士）
显示为「零论文」。

第 ④ 步**反转检索方向**：先按 44 本 IC 相关期刊的 ISSN 用游标深分页**全量抓取**
2008 年至今的论文（约 96 万篇），再对每篇的**每一位作者**用「姓名精确匹配 + **该作者本人
的机构字段**校验」回查名录。因为不经过相关性排序，同名者干扰被彻底绕开。

实测效果：可核实论文的导师 2584 → **3014 人**，零记录 606 → **176 人**。

期刊 ISSN 列表在 `harvest_pool_match.mjs` 顶部的 `JOURNALS` 数组里；
`reenrich_topic.mjs` 顶部的 `ISSN` 是另一套（用于个体补检），两处可按需增删。

#### 第 ⑤ 步为什么不能省

**不要只信任采集过程，要独立复核最终数据。** `validate_pool.mjs` 不看采集逻辑，
只逐条重新核验「被匹配作者的机构是否真的属于该校」。它曾抓出一个致命 bug——
采集脚本把 `SCHOOL_META` 的字段名 `include`/`exclude` 误写成 `src.inc`/`src.exc`，
导致 `new RegExp(undefined)` **匹配一切**、机构校验静默失效（81.7% 的匹配失真）。
当前剔除率 0.1%，高产学者机构一致率约 99%。

> ⚠️ **HTML 实体坑**：Crossref 的机构串里带 HTML 实体
> （`Xi&#x2019;an Jiaotong University`、`Science &amp; Technology`），
> 必须先解码再做正则匹配，否则整所学校的召回率会崩掉——西交曾因此只有 31/156。
> 解码函数 `decodeEnt()` 已内置在采集与补检脚本中。


### 4. 评分与排名

```bash
node tools/score.mjs                        # 指标 + 方向归类 + 强度分
PYTHONPATH=<skill脚本目录> python tools/skill_heuristics.py   # 异常规则 C01–C07
node tools/integrity_check.mjs top260       # 撤稿 / 更正核查
node tools/rank_final.mjs                   # 8 维综合分与全库排名
```

### 5. 课题组主页与招生信息

```bash
node tools/fetch_labs_all.mjs    # 抓取全部有主页的导师（约 5 分钟 / 3085 人）
node tools/analyze_labs.mjs      # 提取招生原话、课题组名
```

原始文本缓存在 `data/raw/lab_pages/<school_key>_<姓名>.txt`，**已抓过的会自动复用**，重跑很快。

> **文件名用 school_key，不要用中文校名前 4 字**——「清华大学」与「清华大学深圳国际研究生院」
> 前 4 字相同，中科院拆分后 6 个所的前 4 字都是「中国科学」，会互相覆盖。
> 若接手的是旧数据，先跑 `node tools/migrate_labpage_names.mjs` 迁移。

#### 招生信号的两条防误判判据（务必保留）

1. **站点模板过滤**：同一语句若在**同校 ≥4 人**的页面上出现，判定为站点新闻栏/导航模板并剔除。
   中科院微电子所官网的新闻栏（「夏令营报名通知」「拟录取名单公示」）曾让该所
   **78/78 人**全部被误标为「在招」；加此判据后降为 0/23。
2. **姓名邻近度**：同时记录招生语句与该人姓名的距离（±200 字内为 `near`）。

改完务必用 `node tools/check_recruit_bias.mjs` 看各校在招占比——
若某校接近 100%，几乎一定是模板误判。

> 招生话术会变。如果只更新招生信息，只跑这两步即可。

### 6. 推荐集与报告

```bash
node tools/curate.mjs            # 构建推荐集（聚焦方向 + 其他方向在招）
node tools/html_db.mjs           # 生成 全库 HTML
node tools/html_recommend.mjs    # 生成 推荐 HTML
node tools/report_final.mjs      # 生成 全库排名报告 MD
node tools/report_recommend.mjs  # 生成 推荐与招生信息报告 MD
node tools/strip_emails.mjs      # 【必跑】兜底清除任何残留邮箱
python tools/make_docx.py "reports/导师库-详细排名报告.md" "reports/导师库-详细排名报告.docx"
python tools/make_docx.py "reports/导师推荐与招生信息.md" "reports/导师推荐与招生信息.docx"
node tools/verify_html.mjs reports/导师推荐.html reports/导师库.html   # 校验 HTML 数据可解析
```

> `strip_emails.mjs` 必须放在最后：它会清洗**字段名**和**字符串里嵌的邮箱**
> （例如导师主页原话"请发送简历至〈邮箱〉"），而生成脚本无法预知这些内容。

> **生成器里的统计数字与院校清单不要写死**——已全部改为从 `mentor_ranked.json` 动态读取。
> 新增学校或拆分单位后，报告文案会自动跟随，无需手改。

### 6.5 名录结构变动时（新增学校 / 拆分公司）

```bash
python tools/clean_rosters.mjs 后接  python tools/prepare_names.py   # 重新生成姓名变体
node tools/find_dups.mjs            # 检查同校同名（必须为 0，否则下游键会互相覆盖）
python tools/disambig_all.py        # 同校同名消歧（加院系/方向后缀）
python tools/fill_name_en.py        # 外文姓名补 name_en（否则拼音会逐字母拆碎）
node tools/check_roster.mjs data/raw/*/roster_*.json   # 名录结构合规校验
node tools/sync_roster_fields.mjs   # 把名录的身份字段同步回 enriched_*.json
```

> **中科院按所拆分**的参考实现见 `tools/split_cas.mjs`：把一个总名录按 `department`
> 字段拆成多份，并为每个所单独配置 Crossref 机构匹配规则（避免所间串号）；
> 拆完后须在 `prepare_names.py` 的 `SKIP_KEYS` 中登记原总名录，防止重复登记。


### 7. 提交

```bash
python tools/git_size.py            # 确认提交体积（建议 <40 MB）
node tools/summary.mjs              # 打印关键数字，用来更新 README 的统计表
node tools/audit_prepublish.mjs     # 【必跑】公开前审计（16 项）
git add -A && git commit -m "data: 2027 春季数据更新" && git push
```

### 8. 公开前审计（每次推送前都要跑）

`node tools/audit_prepublish.mjs` 检查 16 项，**出现 ❌ 阻塞项就不应推送**：

| 检查 | 说明 |
|:--|:--|
| 邮箱残留 | 产物与代码中不得出现任何邮箱（隐私红线） |
| 个人信息 / 本机路径 | 不得出现真实姓名、个人邮箱前缀、主机名、本地目录结构 |
| 硬编码绝对路径 | 脚本须可移植（以脚本位置解析仓库根目录） |
| 评价性用语 | 报告中不得出现"避雷/天坑/不推荐/水平差"等表述 |
| 合规文档齐备 | README / DISCLAIMER / CONTRIBUTING / LICENSE×2 / CITATION / Issue 模板 / CI / 落地页 |
| 数据文件完好 | 全部 JSON 可解析，名录非空且无邮箱值 |
| 相对链接有效 | Markdown 与落地页里的相对链接均可解析 |
| 凭证扫描 | 不得出现 token / 私钥 / 密码 |
| 提交者身份 | 必须全部是 GitHub 匿名邮箱 |
| 统计自洽 | README 声明的人数与数据文件一致 |

## 三、诊断与核查工具

这些脚本不参与数据生产，但在**排查问题、验证质量**时非常有用。
建议每次数据更新后至少跑一遍标 ⭐ 的几个。

| 脚本 | 用途 | 何时用 |
|:--|:--|:--|
| ⭐ `audit_prepublish.mjs` | 公开前审计（16 项：邮箱残留、个人信息、硬编码路径、评价性用语、链接、凭证、提交者身份…） | **每次推送前必跑** |
| ⭐ `check_roster.mjs` | 名录结构校验（字段、类型、重名、外文姓名、邮箱红线） | 采集/合并名录后 |
| ⭐ `quality_report.mjs` | 数据质量综合核查（Top 25 人工过目、S/A venue 分布、机构一致性抽检、字段完整性、各维度与综合分的相关性） | 数据大改后 |
| ⭐ `check_recruit_bias.mjs` | 各校「在招」占比 + 高频重复语句检测 | 招生信息更新后（某校接近 100% 即为模板误判） |
| `anomaly_check.mjs` | 指标矛盾、引用异常、署名结构异常、字段缺失、维度相关性 | 怀疑评分有问题时 |
| ⭐ `clone_selftest.mjs` | **全新克隆自检**：确认只依赖已入库文件的脚本都能跑通、缺中间产物时给出友好提示而非抛栈 | 每次推送前 |
| ⭐ `contamination_scan.mjs` | **逐人计算「论文机构一致率」**，找出可能仍有同名混入或漏收的人 | 改过机构匹配规则后 |
| ⭐ `check_doc_numbers.mjs` | 文档声称的统计数字与实际数据逐项比对 | 更新数据后（README 数字易脱节） |
| `lint_html_js.mjs` | HTML 内嵌脚本的语法、DOM 引用、是否含网络请求 | 改过 HTML 生成器后 |
| `check_html_ui.mjs` | 两个页面的交互控件、可排序列、render 调用一览 | 同上 |
| `decode_affs.mjs` | 一次性解码存量机构串里的 HTML 实体 | 仅在接手旧版数据时 |
| `list_tiers.mjs` | 列出所有被分到 S/A/B 的 venue 供人工核查 | 改过 `classify.mjs` 分层表后 |
| `verify_homepages.mjs` | 主页链接可达性抽查（92–100%）与域名合法性 | 补完主页后 |
| `verify_merged.mjs` | 合并后数据抽查（高产者的机构一致率） | 论文池合并后 |
| `verify_html.mjs` | HTML 内嵌数据可解析、script 闭合、无个人化用词 | 生成 HTML 后 |
| `check_fav.mjs` | 推荐页收藏/导出功能代码完整性 | 改过推荐页后 |
| `who_zero.mjs` | 盘点零论文记录者，并按"无原始论文/被过滤"分类 | 想继续提召回时 |
| `assess_filter.mjs` | 量化 IC 过滤的影响与被过滤的 venue 分布 | 讨论"论文数口径"时 |
| `assess_remaining.mjs` | 盘点剩余缺口（未抓主页、字段缺失、疑似漏检） | 规划下一步时 |
| `gaps.mjs` | 各校召回缺口统计 | 改过机构匹配规则后 |
| `probe_aff.mjs` | 打印某机构在 Crossref 里的**真实机构串写法** | **新增学校时先跑这个** |
| `probe_missing.mjs` | 对某位漏检者单点探测各数据源 | 个别名人召回失败时 |
| `find_dups.mjs` / `find_missing.mjs` | 同校同名检查 / enriched 与名录的差异检查 | 名录结构变动后 |
| `dbstats.mjs` / `summary.mjs` | 数据体检 / 关键数字汇总（后者用于更新 README） | 随时 |
| `git_size.py` | 仓库提交体积统计（建议 <40 MB） | 提交前 |

## 四、常见问题排查

| 现象 | 原因 | 处理 |
|:--|:--|:--|
| 某位知名教授论文数异常少 | 同校同名者挤占了 Crossref 检索结果前 200 条 | 跑 `harvest_pool_match.mjs`（论文池反向匹配）；仍不行用 `reenrich_topic.mjs` 或 `probe_missing.mjs` 单点排查 |
| 某人被计入大量医学/化学论文 | 同名污染 | 已由 `score.mjs` 的非工科期刊过滤；必要时补充 `OFF_FIELD` 词表 |
| 抓取全是乱码 | 目标站点用 GBK | `fetch_pages.mjs` 已自动探测；异常时设 `FORCE_ENC=gbk` |
| `Invoke-WebRequest` 报 schannel 错误 | Windows TLS 凭据问题 | 改用 `curl.exe -k` 或 Node 的 `fetch` |
| Crossref 返回 429 | 请求过密 | 降低 `CONC` 环境变量；Crossref 友好池要求带 `mailto` |
| 产物里又出现邮箱 | 生成脚本把主页文本原样带出 | 跑 `node tools/strip_emails.mjs`，并检查是否有新字段名未被 `EMAIL_KEY` 覆盖 |
| HTML 打开后表格空白 | 数据 JSON 被破坏 | `node tools/verify_html.mjs reports/*.html` 定位 |
| **某所学校整体召回率异常低** | **Crossref 机构串含 HTML 实体**（如 `Xi&#x2019;an Jiaotong University`、`Science &amp; Technology`），正则匹配不上 | 已内置 `decodeEnt()` 解码；若新增学校的名称含撇号或 `&`，务必确认解码后再匹配（西交曾因此只有 31/156，修复后 119/156） |
| 改完匹配规则但数据没变化 | `enrich_crossref.mjs` 默认跳过已存在的产物 | 加 `FORCE=1` 重跑：`$env:FORCE='1'; node tools/enrich_crossref.mjs <school>` |
| 脚本报 `'list' object has no attribute 'get'` | 名录目录里有数组格式的中间产物（`roster_draft.json` / `roster_stage.json`）被 glob 误匹配 | 中间产物命名为 `_draft.json` / `_stage.json`，或依赖脚本内置的跳过逻辑 |
| 同校两位同名教师互相覆盖 | 管线按 `学校\|姓名` 建键 | 跑 `python tools/disambig_all.py` 加括号后缀消歧（`prepare_names.py` 已支持括号不参与读音） |
| 某位知名教授论文数明显偏低 | 同校同名者挤占 Crossref 结果前 200 条 | 先跑 `harvest_pool_match.mjs`（论文池反向匹配）；仍不行用 `reenrich_topic.mjs` 或 `probe_missing.mjs` 单点排查 |
| **某校「在招」比例接近 100%** | 站点新闻栏模板被当成本人招生表述 | 已在 `analyze_labs.mjs` 内置「同校 ≥4 人重复即剔除」判据；用 `check_recruit_bias.mjs` 复查 |
| 某人论文里混入了医学/化学论文 | 跨学科同名他人 | `tools/contamination_scan.mjs` 定位；`score.mjs` 的 `OFF_FIELD` 词表已过滤这类 venue，不影响 IC 计数 |
| 某校论文数明显偏少 | 该校大量论文的机构串只写实验室名（不含校名） | 在该校 include 规则里补上重点实验室名；先用 `probe_aff.mjs` 看真实写法 |
| 主页链接点开是报错 | 原采集源主机已下线（如 `sourcedb.sim.cas.cn`） | 跑 `node tools/fix_dead_links.mjs` 置空死链；再用 `verify_homepages.mjs` 抽查可达性 |
| 自动补的职称明显不对（如整批出现「院士」） | 页面噪声文本被误当职称 | **错误职称比缺失更糟**（污染头衔评分）。只接受「姓名真实出现 + 职称在姓名前后 40 字窗口内 + 排除导师/招生类表述」的严格匹配，且不自动判定院士 |
| 拉取别人的 clone 后脚本报路径错误 | 旧版脚本含硬编码绝对路径 | 已全部改为以脚本所在目录的上一级解析仓库根目录；若从旧版 fork，需自行替换 |

## 五、扩展方向

- **增加学校**：见 [CONTRIBUTING.md](../CONTRIBUTING.md) 第二节；
- **增加期刊层级**：改 `tools/classify.mjs` 的 venue 分层表（S/A/B）；
- **增加方向标签**：改 `tools/curate.mjs` 顶部的 `GROUPS` 数组（顺序=匹配优先级，多标签）；
- **增加分析维度**：在 `tools/score.mjs` 里补充指标，并在 `tools/rank_final.mjs` 的权重表里登记。

## 六、入库边界：哪些文件进仓库，哪些不进

公开仓库必须让人**克隆下来就能用**，同时不能把几十 MB 的中间产物也带进去。
因此工具分为两类：

| 类别 | 依赖 | 克隆后能否直接跑 | 代表脚本 |
|:--|:--|:--|:--|
| **A 类** | 只读**已入库**产物：`mentor_ranked.json`、`curated.json`、`lab_pages.json`、各校 `roster_*.json` | ✅ 能 | `summary` / `check_doc_numbers` / `html_db` / `html_recommend` / `report_final` / `report_recommend` / `list_tiers` / `anomaly_check` / `audit_prepublish` |
| **B 类** | 需要**未入库的中间产物**：`enriched_<key>.json`、`name_variants.json`、`mentor_db.json` | ❌ 需先按「全量重建流程」重跑 | `score` / `contamination_scan` / `assess_filter` / `decode_affs` |

B 类脚本在缺文件时**必须给出友好提示并以退出码 0 结束**，不要抛栈。

> **每次推送前跑一遍 `node tools/clone_selftest.mjs`**，
> 它会逐个执行 A 类脚本确认可运行，并验证 B 类脚本的缺失提示是否友好。

#### 一句话验证可复现性

```bash
git clone --depth 1 <仓库地址> /tmp/x && cd /tmp/x
node tools/html_db.mjs && node tools/report_final.mjs
# 产物应与仓库中的 reports/ 完全一致（MD5 相同）
```
