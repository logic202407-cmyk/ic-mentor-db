## 1. 本地环境准备

| 项 | 要求 | 说明 |
|:--|:--|:--|
| 操作系统 | Windows 10/11 **主测** | Linux/macOS 可运行；`.cmd` 脚本不可用，请用手动命令 |
| Python | 3.11+（主测 3.12） | 用了 `X \| None` 等新语法与 `pathlib` 新接口 |
| Node.js | 可选，≥ 20 | 只在跑前端竞态测试时需要 |
| 磁盘 | 仓库约 125 MB | 另有运行期目录与嵌入模型缓存，见 §4 |

```bat
:: 1) 创建虚拟环境（只需一次；首次需要联网）
py -3 -m venv .venv

:: 2) 装运行时依赖
.venv\Scripts\python.exe -m pip install -r workbench\requirements.txt

:: 3) 验证：语法 + 编码（都应当 exit 0）
.venv\Scripts\python.exe -m compileall -q workbench
.venv\Scripts\python.exe -m workbench.tools.encoding_audit
```

**两个环境变量**（都只在当前终端生效，不写进仓库）：

| 变量 | 作用 |
|:--|:--|
| `PYTHONIOENCODING=utf-8` | 中文 Windows 控制台默认 GBK，被测脚本输出中文时可能抛 `UnicodeEncodeError`。**跑测试与检查前建议先设** |
| `MENTOR_WORKBENCH_DATA` | 覆盖运行期数据目录（默认 `.workbench-data`）。**做破坏性实验时指向临时目录**，不要拿真实调查记录做实验 |

```powershell
$env:PYTHONIOENCODING = "utf-8"
```

> 仓库里所有「给人看」的文本是 UTF-8；所有「被程序读」的文本（`.cmd`、`requirements.txt`、
> `.gitattributes`、`.gitignore`）必须保持纯 ASCII 或无 BOM，由 `encoding_audit` 把关，
> 原因见 §12 第 1 条。

## 2. 依赖：运行时 vs 开发期

依赖清单只有一个权威来源：[`workbench/requirements.txt`](../workbench/requirements.txt)。
它分两段：

1. **运行时（文件上半部分，有版本号）**：`fastapi`、`uvicorn`、`requests`、`beautifulsoup4`、
   `numpy`、`urllib3`、`fastembed`。装了才能启动服务。
2. **可选 / 开发期（文件末尾注释）**：`markdown`、`pypdf`、`pypdfium2`、`pillow`、`pdfplumber`、
   `playwright`。工作台**不装也能跑**，只有对应的专项工具/脚本才需要。注释里写了每个包服务于哪个脚本。

维护时的三条纪律：

- **新增模块级第三方 import，必须同步登记到 requirements.txt**，否则 CI 的
  `workbench/tests/test_requirements.py` 会红（它用 AST 扫模块级 import，不真跑）。
- **能惰性导入就惰性导入**。`beautifulsoup4` 曾经是模块级导入，导致只读已存档案的检查在没装 bs4
  的环境里直接 `ModuleNotFoundError`；把导入挪进使用处之后，CI 也不必为读档案装解析器。
- **requirements.txt 保持纯 ASCII**（含注释）。pip 用系统区域编码读这个文件，中文注释会让
  `pip install -r` 直接 `UnicodeDecodeError`。

## 3. 启动、关闭与健康检查

### 3.1 一键脚本（Windows）

| 脚本 | 作用 |
|:--|:--|
| `启动.cmd`（英文系统 `start.cmd`，内容相同） | ① 没有 `.venv` 就创建并装依赖 → ② 起服务并轮询健康检查（最多 20 秒）→ ③ 打开浏览器 |
| `停止.cmd`（`stop.cmd`） | 找监听 8765 的进程并 `taskkill`；没有在跑就只提示 |

两个脚本都**刻意写成纯 ASCII**：`cmd.exe` 用 OEM 代码页解析 `.cmd`，写中文会把行切坏。
中文只留在**文件名**与文档里，别再往脚本里加中文。

### 3.2 手动命令（跨平台，维护时更常用）

```bat
.venv\Scripts\python.exe -m uvicorn workbench.app:app --host 127.0.0.1 --port 8765
```

健康检查（另开一个终端）：

```bat
curl.exe http://127.0.0.1:8765/api/health
```

实测返回：

```json
{"ok":true,"model":"BAAI/bge-small-zh-v1.5","storage":"local"}
```

- `model` 是**配置的模型名**，不代表模型已经加载成功；加载失败会在检索时回落到 BM25（§9）。
- `storage` 恒为 `local` —— 本项目没有远程存储。

### 3.3 端口占用

启动脚本先探测 8765 是否已在监听：已监听就只打开浏览器。若手动启动报
`[Errno 10048] only one usage of each socket address`，说明端口被占：

```bat
netstat -ano | findstr ":8765"
:: 记下最后一列 PID，然后
taskkill /PID <PID> /F
```

或者直接换端口跑：`--port 8766`（此时记得同时改浏览器地址）。

### 5.4 打包与登记：两个必须知道的机制

**① 逐人档案为什么要打包。** 逐人档案是 6 千多个散 JSON（合计约 28 MB）。为了让「clone 下来
就有论文与招生记录」，`pack_research_bundle` 把它们压成一个 gzip JSONL 放进仓库：

```bat
.venv\Scripts\python.exe -m workbench.tools.pack_research_bundle           :: 重新打包
.venv\Scripts\python.exe -m workbench.tools.pack_research_bundle --check   :: 只比对是否落后
.venv\Scripts\python.exe -m workbench.tools.pack_research_bundle --manifest :: 只重写清单
.venv\Scripts\python.exe -m workbench.tools.pack_research_bundle --force    :: 允许把副本改小
```

`--check` 的三条判据（实测输出见附录 B）：副本与清单是否一致；本机档案是否比副本新；
**本机档案明显少于副本时判为「本机不完整」并 SKIP 新鲜度比对**——这是为了避免在只有几条档案的
机器上把仓库里 6498 条的副本覆盖掉。真要缩小副本必须显式 `--force`。

**② 来源登记表是「来源可追溯」的落点。** `research_sources.json` 记录每个 `key` 的页面、
抓取时间与覆盖说明；`public_research.source_registry()` 读它，`registered_source()` 用它判断
某条记录的来源是否可信。**新增来源必须在这里登记**，否则该来源的记录在核对时会缺少出处。

## 6. 数据来源扩充流程（新增一个来源模块）

采集器的设计是「**加一所学校 = 加一个模块**」，不需要改采集器本身：
`collect_engineering_scale.discover_sources()` 会在运行时扫描 `workbench/sources/` 下所有模块。

### 6.1 模块契约

`workbench/sources/<key>.py` 必须暴露两个名字（详见 `workbench/sources/__init__.py`）：

```python
SPECS = ({                       # 一个模块可以登记多个页面/系
    "key": "example_control",    # 全局唯一、稳定的 key（会写进来源登记表）
    "code": "0811",              # 4 位一级学科代码
    "institution": "示例大学",
    "department": "自动化学院",
    "discipline": "控制科学与工程",
    "listing": "https://.../szdw.htm",   # 名录页
    "max_pages": 1,
},)

def parse(html: str, url: str, spec: dict) -> list[dict]:
    ...
```

### 6.2 五条红线（不是风格偏好，是项目约束）

1. **不写邮箱、不写电话**：任何联系方式字段都不进 rows。
2. **不编造**：页面没写研究方向，就留 `NO_DIRECTION`（`"方向待补"`）；**绝不把职称当方向**
   （`教授` 是职级，不是研究方向）。
3. **每条记录带来源**：用 `roster_row(...)` 生成行，它会写入名录页 URL 与抓取时间；
   有个人页时同时作为 `homepage`。
4. **姓名必须是真人**：`roster_row` 会用 `NAME_RE` 校验；导航文字、办公室名、研究所标题
   必须在调用前过滤掉，不要指望校验兜底。
5. **跳过非教学单位**（党委 / 工会 / 离退休 / 办公室）；研究所、重点实验室、协同中心保留。

### 6.3 操作步骤

```bat
:: 1) 先看页面真实结构（不要凭印象写选择器）
::    把名录页存成 fixture，写完 parser 立刻做回归
::    workbench/tests/fixtures/<key>.html  +  一条 parse() 用例

:: 2) 干跑：只解析、只报告，不落盘
.venv\Scripts\python.exe -m workbench.collect_engineering_scale --dry-run --only example_control

:: 3) 真采（可先 --limit 控制条数；--enrich 会顺带读个人页）
.venv\Scripts\python.exe -m workbench.collect_engineering_scale --only example_control --enrich

:: 4) 合并进目录（按 (institution, department, name) 去重，不覆盖已有记录）
.venv\Scripts\python.exe -m workbench.collect_discipline_catalog

:: 5) 验收三连
.venv\Scripts\python.exe -m workbench.tools.audit_new_sources --limit 4
.venv\Scripts\python.exe -m workbench.tools.distribution_audit --only-failing
.venv\Scripts\python.exe -m workbench.tools.data_quality --check

:: 6) 若逐人档案有变化，重新打包并核对清单
.venv\Scripts\python.exe -m workbench.tools.pack_research_bundle
.venv\Scripts\python.exe -m workbench.tools.pack_research_bundle --check
```

`--only KEY` 很重要：**一个不稳定的站点不该让整批采集失败**。

### 6.4 采集纪律（照抄自采集器实现，不是建议）

- **明确 UA 与超时**：请求带浏览器 UA、`Accept-Language: zh-CN`、`timeout=(10, 30)`。
- **失败重试 + 退避**：单页最多 3 次，退避 1.5s × 尝试序号。没有重试时，一次读超时会
  **静默截断分页**（真实发生过：242 行的名录只采到 150 行）。
- **字符集判定要保守**：先信服务器声明的 charset（除非是 requests 的 ISO-8859-1/ascii 兜底），
  再依次尝试 UTF-8、GB18030；如果按声明解码没有得到中文而字节里确实有中文，就回退重解。
  这条规则来自一次事故：某页声明 UTF-8 而 chardet 猜成 `ptcp154`，覆盖声明后
  230 人的页面解析出 **0 行**。
- **保留来源时间**：每条记录都带 `fetched_at`，这是「可核验」的前提，不要为了体积丢掉。
- **限速与并发**：采集脚本按批次串行/小并发运行，给目标站点留余量；
  新增来源时沿用同一批参数，不要为了快而压满对方站点。

### 6.5 离线快照与离线重解析

采集到的页面会缓存到 `.workbench-data/research-pages/`（按 URL 哈希命名）。有两个只读开关：

```bat
.venv\Scripts\python.exe -m workbench.public_research --offline      :: 只用已存 HTML 重解析，不联网
.venv\Scripts\python.exe -m workbench.public_research --cached-only  :: 只重解析此前能读通的档案
```

用途：解析规则改了以后，**用同一批快照验证改动的效果**，而不是重新抓一遍（既慢又不可比）。

## 7. 导师身份核查原则

这一节决定「同名记录能不能合并」。**合并错了比漏掉严重得多**，所以规则偏保守。

### 7.1 三态而不是二态

`disambiguate_names` 输出三种判定，永远不存在「不是同一人就是不同人」的二分：

| 状态 | 什么时候给 | 后续动作 |
|:--|:--|:--|
| `same_person` | **同一专属个人主页 + 同机构** | 才允许视为同一人 |
| `different_person` | 各有互不相同的专属主页，且院系/学科冲突 | 保留为两条独立记录 |
| `unknown` | 缺主页、共用名录页、证据不足 | **进人工待核队列**，系统不自动合并 |

### 7.2 判等优先级：专属主页 > 嵌入相似度

同校履历模板化会把相似度整体抬高，因此**先看主页证据，再看相似度**。
两个 URL 处理函数方向相反、不能互相顶替：

| 函数 | 保留什么 | 用来判断 |
|:--|:--|:--|
| `canonical_home(url)` | 抹掉协议、`www`、锚点、**整个查询串** | 「这是不是一个名录/列表页」——用于按标题、文件名识别共用页 |
| `identity_home(url)` | 抹掉协议/`www`/锚点，**保留查询串** | 「这两个 URL 是不是同一个专属页」——查询串常常就是页面 id |

反面教材（仓库里有用例钉住）：某些站点的个人页长成 `p.php?aid=100` / `p.php?aid=104`，
`canonical_home` 会把 **111 个不同的人压成 11 个 URL**。所以**判等只能用 `identity_home`**。

### 7.3 `unknown` 去哪

```bat
.venv\Scripts\python.exe -m workbench.disambiguate_names --review     :: 产出同校同名待核队列
```

队列落在 `.workbench-data/name-disambiguation/`，界面上的「同名待核」提示读的就是它。
人工标注走盲标流程：

```bat
.venv\Scripts\python.exe -m workbench.disambiguate_names --export-human 盲标表.csv   :: 不含模型分数
.venv\Scripts\python.exe -m workbench.disambiguate_names --import-human 盲标表.csv   :: 样本足够才重算
.venv\Scripts\python.exe -m workbench.disambiguate_names --human-status               :: 看标注进度
```

**人工金标准尚未建立**（协议与空白标注表在 `workbench/evaluation/`）。在此之前，
任何「一致率」都只能表述为**两套程序规则之间**的一致性，不得写成人工准确率。
`--gold` 产出的是**程序辅助核验集**，不是人工金标准。

## 8. 检索索引与缓存（改完数据为什么"没生效"）

### 8.1 五种模式

`search.SEARCH_MODES = {semantic, keyword, bm25, hybrid, auto}`：

| 模式 | 做法 |
|:--|:--|
| `keyword` | 字面命中比率（去空白 + 小写后比对） |
| `bm25` | 中文按 **bigram**、拉丁按整词切分的 BM25 倒排索引（不依赖 jieba） |
| `semantic` | 嵌入模型余弦相似度 |
| `hybrid` | BM25 与向量各半（权重可被 API 覆盖） |
| `auto` | 英文缩写（`VLSI`/`MEMS`/`EDA` 这类）走 BM25，其余走混合 |

弱相关不硬推：混合分低于阈值直接返回空；语义最高分低于 `SEMANTIC_EMPTY_TAU` **且**全库
没有任何字面命中时也返回空。两个阈值都来自 `retrieval_eval` 的实跑产物，不要手调。

### 8.2 两级缓存与失效规则

| 缓存 | 位置 | 键 | 什么时候自动失效 |
|:--|:--|:--|:--|
| 进程内语料缓存（文档文本 + BM25 索引） | 内存，最多 2 份（LRU） | `(project_id, 文档内容指纹)` | 档案内容一改，指纹就变，自动重建 |
| 向量缓存 | `.workbench-data/indexes/<project_id>.npz` | npz 里存 `fingerprint` + `model` | 指纹不一致**或模型名变了**就重算 |

**所以：改了某个人档案里的方向/简介，语料指纹随即改变，检索结果会自己跟上**，
不需要手工删缓存。真正需要手工干预的只有三种情况：

1. 换了模型（`MODEL_NAME` 改了）——npz 会因 `model` 字段不符而重算；
2. 怀疑 npz 损坏、但又没触发指纹失效——删掉 `.workbench-data/indexes/<project_id>.npz`；
3. 想看「首建」耗时——同样删 npz，再跑一次语义检索。

`sizes`：单份全量语料缓存实测约 100 MB（文档 + 归一化文本 + BM25 数组 + 30 MB 向量矩阵），
所以进程内只留 2 份；淘汰只影响速度，不影响正确性。

## 9. 嵌入模型（**可选能力**，缺失时自动降级）

| 项 | 内容 |
|:--|:--|
| 模型 | `BAAI/bge-small-zh-v1.5`（`search.MODEL_NAME`） |
| 推理 | 由 `fastembed` 在**本地**完成，不调用任何在线 API，不需要 Key |
| 权重缓存 | `.workbench-data/models/`（首次使用自动下载，本机实测约 90 MB） |
| 缺失时 | `semantic` 请求**不报 500**：自动回落到 BM25，结果里带 `fallback` 说明 |

这条降级路径是硬要求，不是兜底：

```
fallback: "向量模型不可用，已回落到 BM25（<异常类型>）"
```

**维护时不要把它写成「必需」**。判断当前机器能不能用模型，看两处：

1. `/api/health` 的 `model` 字段（配置值）；
2. 真发一次语义检索，看返回里有没有 `fallback`（**这才是有没有生效的证据**）。

需要模型才能跑的是「模型专项」用例（语义检索、方向推断的一部分），其余业务测试与
来源解析测试都不需要模型。

## 10. 数据备份与恢复

用户最重要的资产不是公开数据，而是**自己在界面上写下的核查记录**
（`.workbench-data/projects/`、`investigations/`）。它重建不了，所以要有备份。

```bat
:: 打包（zip 内含 manifest：时间、条数、每个文件的 sha256）
.venv\Scripts\python.exe -m workbench.tools.backup_records --backup

:: 列出已有备份（不带参数等同于 --list）
.venv\Scripts\python.exe -m workbench.tools.backup_records --list

:: 只校验，不动数据
.venv\Scripts\python.exe -m workbench.tools.backup_records --verify backups/records-<时间>.zip

:: 恢复（先校验 → 把当前记录另存 before-restore → 逐文件原子写回）
.venv\Scripts\python.exe -m workbench.tools.backup_records --restore backups/records-<时间>.zip --yes
```

三个设计点，改代码时别破坏：

1. **`--restore` 前一定先备份当前记录**（`backups/before-restore/`）。恢复本身也可能是误操作。
2. **任何一份坏 JSON 都让整次恢复中止**：先全部解析、再落盘，不做「恢复了一半」。
3. **备份包里的文件名不可信**：manifest 的名字只接受 `projects/<x>.json`、
   `investigations/<x>.json` 两种形态，`../` 之类直接拒绝。

与运行期存储的分工（`workbench/storage.py`）：

| 入口 | 用在哪 |
|:--|:--|
| `file_lock(target)` | 所有「读—改—写」一侧加锁；等锁超时抛 `LockTimeoutError` |
| `atomic_write_json(path, payload)` | 唯一临时文件 + `fsync` + `os.replace`；覆盖前留 `.bak` |
| `read_json(path)` | 损坏时保留 `.corrupt-<时间>` 副本、尝试从 `.bak` 恢复，恢复不了抛 `DataCorruptError` |
| `restore_backup(path)` | 把 `<path>.bak` 手工恢复到正式文件（**单文件级**的最后手段） |

`restore_backup` 与 `backup_records --restore` 是两件事：前者恢复**单个 JSON 的上一版**，
后者恢复**整个记录集**。用错会丢数据，先想清楚再动手。

## 11. 测试与 CI

### 11.1 分层

| 层 | 命令 | 需要模型 | 说明 |
|:--|:--|:--|:--|
| 快速校验 | `compileall` + `encoding_audit` + `check_readme_badges` | 否 | 秒级，CI 的 `workbench` job |
| 全部业务测试 | `python -m unittest discover -s workbench/tests` | 否 | 56 个测试模块；用例总数见 README 徽章（由 `check_readme_badges` 校验，不要在这里写死） |
| 模型专项 | 语义检索 / 方向推断相关用例 | 是 | 本地有模型缓存时才跑；CI 刻意不装 |
| 前端竞态 | `node --test workbench/tests/test_ui_races.cjs workbench/tests/test_research_ui.cjs` | 否 | 需要 Node ≥ 20 |

```bat
:: 跑单个模块（改哪测哪，最快）
.venv\Scripts\python.exe -m unittest workbench.tests.test_storage_safety -v

:: 跑一组
.venv\Scripts\python.exe -m unittest workbench.tests.test_report_sync workbench.tests.test_facts_consistency -v
```

测试用标准库 `unittest`，**不需要 pytest**（仓库里若出现 `.pytest_cache/` 属环境残留，已 gitignore）。

### 11.2 干净 clone 上会 skip 的是哪一批

**这不是缺陷，是有意的**：某些断言只有在「所有者本机保留了不随仓库分发的材料」时才有意义。

| 来源 | skip 条件 |
|:--|:--|
| `test_report_sync` / `test_pdf_layout` / `test_teleprompter` 里的「本机保留材料」用例 | 对应材料文件不存在 |
| `test_privacy_audit` 的严格用例 | 只有设了 `PRIVACY_AUDIT_STRICT=1` 才跑 |
| `test_retrieval_eval` 的部分用例 | 评测产物或语料向量未生成 |
| `test_research_bundle` / `test_student_observation` | 样本里没有满足条件的记录 |

对应的**核心逻辑断言都有临时目录版本**，在干净 clone 上照常执行（例如报告同步的哈希判据、
PDF 页数上限、脚本解析、事实表跳过契约）。所以「clean clone 全绿」并不依赖那些 skip。

### 11.3 CI 的三个 job

`.github/workflows/validate.yml`：

| job | 触发 | 装什么 | 干什么 |
|:--|:--|:--|:--|
| `validate` | push / PR / 手动 | Node 20 | 早期专题的数据与 HTML 产物校验（邮箱红线、JSON 可解析、字段完整） |
| `workbench` | 同上 | 只有 `pypdf` + `requests` | `compileall`、`encoding_audit`、`check_readme_badges`、报告材料两条检查 |
| `full` | PR / main / 手动 | fastapi/httpx/requests/bs4/numpy/pyyaml/pypdf/pypdfium2/pillow | 全部 Python 测试 + 前端竞态 + `check_facts_consistency` + `data_quality --check` |

两条纪律：

- **CI 不装 `fastembed` / `onnxruntime`**（几百 MB，且模型测试只在本地跑）。看到有人往 CI 加
  这两个包，先问清楚为什么。
- `workbench` job 里那两条「报告材料」检查，在材料不随仓库分发时**会显式打印
  `状态: SKIP — …未随仓库发布，已跳过` 并返回 0**。这是有意设计：跳过必须说出来，
  不能静默当作校验通过（`--strict` 可把缺失变成失败）。

### 11.4 关键数字别靠人记得更新

- `check_readme_badges` 校验 README 徽章（测试数）与体积表；**`--fix` 就地改正**。
  新增/删除测试方法、增删入库文件后都要重跑。
- `check_facts_consistency` 把对外材料里的数字钉到实际数据上；改了数据或改了那些句子都要重跑。
  它维护一张显式声明表：登记过的句子被改写会报「未找到」，数字对不上会报「文中写 X 实际 Y」。
- `distribution_audit` 校验「每个工学学科的最大单一机构占比 < 60%」。**这是硬标准**，
  新增来源时最常见的失败就是让某学科被一所学校占满。

## 12. 常见错误与排查

1. **`UnicodeEncodeError: 'gbk' codec can't encode character ...`**
   中文 Windows 控制台的编码是 GBK，而脚本输出里有 GBK 之外的字符。
   处理：`$env:PYTHONIOENCODING = "utf-8"` 再跑。**这是显示问题，不是数据损坏。**

2. **`pip install -r workbench/requirements.txt` 报 `UnicodeDecodeError`**
   requirements.txt 被写入了中文或 BOM。pip 用系统区域编码读它。
   处理：把该文件恢复成纯 ASCII（注释也只能是英文）；`encoding_audit` 会替你抓这类问题。

3. **`.cmd` 双击后报 `'on.exe' 不是内部命令` 之类的怪错**
   批处理里混入了 UTF-8 中文：`cmd.exe` 用 OEM 代码页解析，会把行切断。
   处理：`.cmd` 只写 ASCII；中文提示交给 Python 或文档。

4. **`[Errno 10048]` / 端口被占**
   `netstat -ano | findstr ":8765"` 找到 PID → `taskkill /PID <PID> /F`，或换 `--port`。

5. **语义检索突然变慢 / 首次检索卡很久**
   首次会下载并加载嵌入模型（几十 MB）。看 `.workbench-data/models/` 是否有内容；
   离线环境会失败并**自动回落 BM25**，响应里带 `fallback` —— 这是预期行为，不是崩溃。

6. **`DataCorruptError: 数据文件损坏：<name>（已保留副本 …）`**
   JSON 解析失败。原文件**没有被覆盖**，损坏副本留在旁边。
   处理顺序：先看 `.corrupt-<时间>` 文件；再用 `restore_backup(path)` 或
   `backup_records --restore` 从 `.bak` / 备份恢复；最后才考虑重建。
   **不要手动删掉损坏文件**——那会丢掉唯一的取证材料。

7. **`LockTimeoutError: 另一个保存操作仍在进行，请稍后重试`**
   同一文件的写操作没结束（并发保存，或上次异常退出留下的锁）。
   锁文件是 `<target>.lock`，正常情况下保留即可；持续超时才排查是否有残留进程。

8. **`pack_research_bundle --check` 输出 `新鲜度：SKIP（本机档案明显少于仓库副本 …）`**
   说明这台机器只有少量本机档案。这是设计好的保护：不让本机不完整的数据覆盖仓库副本。
   确认要缩小副本时才用 `--force`。

9. **`privacy_audit` 报 `[✗ FAIL] personal-records`，指出 `.work/...` 下的文件**
   本机临时/备份目录里有含调查记录字段的 JSON。`privacy_audit` 是**本机合规自检**，
   会扫描工作区里所有文本；这些目录已 gitignore，不会入库。
   处理：把备份挪出工作区（或清理临时目录）后重跑。

10. **CI 红在 `check_readme_badges`：徽章/体积表与实测不一致**
    改了测试数量或入库文件后的正常现象。本地跑 `--fix`，把改动一起提交。

11. **新增来源后「数据没变化」**
    先确认三件事：`--only KEY` 拼写对；`collect_discipline_catalog` 是否重跑过（合并产物）；
    记录是否因为 `(institution, department, name)` 重复被去重跳过。

## 13. 协作与提交纪律

### 13.1 分支与提交粒度

- 从 `main` 切短分支，一个分支只做一件事（一次数据扩充、一次缺陷修复）；
- **一次提交只做一类改动**：数据扩充 / 代码修复 / 文档更新分开。混在一起的提交无法回滚；
- 提交信息写清「为什么」而不只是「改了什么」——半年后回看时，只有原因有用。

### 13.2 不要 `git add .`

仓库里有大量按需生成、体积可观的产物，`git add .` 极容易把不该提交的东西带上。
**按路径显式添加**：

```bat
git add workbench/reference/official_faculty.json
git add workbench/sources/example_control.py workbench/tests/fixtures/example_control.html
git status --short          :: 提交前必看这一行
```

### 13.3 永远不要提交的东西

| 内容 | 位置 | 原因 |
|:--|:--|:--|

## 附录 A：维护工具清单（`workbench/tools/`）

只列维护时会用到的，全部 `--help` 可用（附录 B 有验证记录）。

| 工具 | 用途 | 典型用法 |
|:--|:--|:--|
| `encoding_audit` | 被外部程序读取的文件是否纯 ASCII / 无 BOM | `--verbose` 列出每个被检查文件 |
| `check_readme_badges` | README 徽章（测试数）与体积表 | `--fix` 就地改正 |
| `check_facts_consistency` | 对外材料数字 vs 实际数据 | `--json out.json` 落盘；`--strict` 把材料缺失当失败 |
| `data_quality` | 数据质量报告（记录≠自然人、覆盖、缺失字段） | `--check` 只算不写 |
| `distribution_audit` | 各学科最大单一机构占比（< 60% 硬标准） | `--only-failing`、`--json` |
| `audit_new_sources` | 来源红线审计（来源缺失、homepage 回落名录页） | `--limit N`、`--key KEY` |
| `pack_research_bundle` | 逐人档案打包与清单 | `--check` / `--manifest` / `--force` |
| `backup_records` | 调查记录备份 / 校验 / 恢复 | `--backup` / `--verify` / `--restore --yes` |
| `privacy_audit` | 隐私与合规自检（14 项） | `--check`（有 FAIL 时退出 1）、`--only ID` |
| `scan_duplicate_people` | 目录内同机构同名重复检查（无参数） | 直接跑，输出重复组 |
| `report_facts` | 打印报告需要的事实表 | `--json` |
| `ui_smoke` | 界面运行时冒烟（需服务在跑） | `--base`、`--mentor` |
| `acceptance` | 上传前验收总闸（串起上面多数检查） | `--skip-ui`、`--json` |
| `publish_ai_artifacts` | 把 AI 产物同步进仓库副本 | `--check` 只比对 |
| `pack_eval_artifacts` | 整理评测产物副本（供 `/eval` 读取） | `--check` |
| `check_report_sync` / `check_pdf_limits` / `pdf_layout_check` | 本机保留的报告材料三件套校验（同步、页数/体积、版式） | 材料不存在时显式 SKIP 并 exit 0；`--strict` 可改判失败 |
| `make_teleprompter` / `make_evidence_log` / `render_evidence` / `make_aic_html` / `generate_visual_assets` | 材料生成类脚本，依赖本机素材 | 见各自 `--help` / 文件头 |
| `demo_urls` / `recording_readiness` | 演示链接与录制前就绪检查（需服务） | `--base` |
