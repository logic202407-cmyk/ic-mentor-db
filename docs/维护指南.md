# 维护指南（面向后续维护者）

> 这份文档写给**接手更新本项目的同学**。数据不是一次性的——每学期都该刷新一次。
> 全流程零成本（只用免费公开 API），单人一天可以跑完全套。

---

## 一、数据更新的节奏建议

| 时机 | 更新什么 | 原因 |
|:--|:--|:--|
| **每年 9–10 月** | 全量重建（师资名录 + 论文 + 课题组主页） | 新学年开始，师资与招生信息变动最大 |
| **每年 3–4 月** | 只刷新课题组主页（第 9–10 步） | 夏令营招生信息集中在春季发布 |
| **随时** | 收到 Issue 更正时，单独修数据并重新生成报告 | 权利人诉求优先，承诺 7 个工作日 |

## 二、全量重建流程

### 0. 环境

```bash
node -v      # 需要 ≥18（用到原生 fetch）
python -V    # 需要 ≥3.10
pip install pypinyin python-docx
```

### 1. 更新师资名录

每所学校的名录在 `data/raw/<school_key>/roster_<school_key>.json`。刷新方式二选一：

- **增量检查**：打开 `sources` 字段里的 URL，对比官网人数与本地 `faculty` 长度，补齐新增教师；
- **整校重抓**：参照 [CONTRIBUTING.md](../CONTRIBUTING.md) 第二节的字段规范重抓。

> ⚠️ 采集三条铁律：① 只抓公开可访问页面；② 请求间隔 ≥300 ms、并发 ≤12；
> ③ **不写邮箱**（`email` 一律 `null`），不编造任何字段。

### 2. 清洗与姓名变体

```bash
node tools/clean_rosters.mjs     # 去邮箱 + 过滤简历片段类垃圾关键词
python tools/prepare_names.py    # 生成 name_variants.json（多音字异读组合）
```

`prepare_names.py` 里的 `SCHOOL_META` 需要为每所学校配置：

```python
"xx": {
    "school": "XX大学",
    "include": r"xx university|xx univ",          # Crossref 机构串匹配（正则，忽略大小写）
    "exclude": r"xx university of science|other",  # 需要排除的近似机构名
},
```

**这一步最影响召回率**，改完建议用 `node tools/gaps.mjs` 看各校缺口。

### 3. 论文检索（三步走，缺一不可）

```bash
node tools/enrich_crossref.mjs              # 全量：姓名 + 机构联合检索（约 15 分钟 / 2114 人）
node tools/reenrich_low.mjs 2               # 补检一：论文数 ≤2 的教授，改用纯姓名检索
node tools/reenrich_topic.mjs 2             # 补检二：按 IC 核心期刊 ISSN 定向检索
```

**为什么要补检**：中文拼音重名极严重，**同校内也可能重名**。
第 3 步按「作者名 × 特定期刊 ISSN」检索，能绕开同名者挤占前 200 条结果的问题——
实测把「有 S 级产出人数」从 79 提升到 291。

期刊 ISSN 列表在 `reenrich_topic.mjs` 顶部的 `ISSN` 数组里，可按需增删。

### 4. 评分与排名

```bash
node tools/score.mjs                        # 指标 + 方向归类 + 强度分
PYTHONPATH=<skill脚本目录> python tools/skill_heuristics.py   # 异常规则 C01–C07
node tools/integrity_check.mjs top260       # 撤稿 / 更正核查
node tools/rank_final.mjs                   # 8 维综合分与全库排名
```

### 5. 课题组主页与招生信息

```bash
node tools/fetch_labs_all.mjs    # 抓取全部有主页且论文≥3 的导师（约 5 分钟 / 1000 人）
node tools/analyze_labs.mjs      # 提取招生原话、课题组名
```

原始文本缓存在 `data/raw/lab_pages/*.txt`，**已抓过的会自动复用**，重跑很快。

> 招生话术会变。如果只更新招生信息，只跑这两步即可。

### 6. 推荐集与报告

```bash
node tools/curate.mjs            # 构建推荐集（聚焦方向 + 其他方向在招）
node tools/html_db.mjs           # 生成 全库 HTML
node tools/html_recommend.mjs    # 生成 推荐 HTML
node tools/report_final.mjs      # 生成 全库排名报告 MD
node tools/report_recommend.mjs  # 生成 推荐与招生信息报告 MD
node tools/strip_emails.mjs      # 【必跑】兜底清除任何残留邮箱
python tools/make_docx.py "reports/导师库-详细排名报告.md" "reports/导师库-详细排名报告.docx"
python tools/make_docx.py "reports/导师推荐与招生信息.md" "reports/导师推荐与招生信息.docx"
node tools/verify_html.mjs reports/*.html   # 校验 HTML 数据可解析
```

> `strip_emails.mjs` 必须放在最后：它会清洗**字段名**和**字符串里嵌的邮箱**
> （例如导师主页原话"请发送简历至〈邮箱〉"），而生成脚本无法预知这些内容。

### 7. 提交

```bash
python tools/git_size.py     # 确认提交体积（建议 <40 MB）
node tools/summary.mjs       # 打印关键数字，用来更新 README 的统计表
git add -A && git commit -m "data: 2027 春季数据更新" && git push
```

## 三、常见问题排查

| 现象 | 原因 | 处理 |
|:--|:--|:--|
| 某位知名教授论文数异常少 | 同校同名者挤占了 Crossref 检索结果前 200 条 | 跑 `reenrich_topic.mjs`；仍不行就手动查 `tools/probe_person.mjs` |
| 某人被计入大量医学/化学论文 | 同名污染 | 已由 `score.mjs` 的非工科期刊过滤；必要时补充 `OFF_FIELD` 词表 |
| 抓取全是乱码 | 目标站点用 GBK | `fetch_pages.mjs` 已自动探测；异常时设 `FORCE_ENC=gbk` |
| `Invoke-WebRequest` 报 schannel 错误 | Windows TLS 凭据问题 | 改用 `curl.exe -k` 或 Node 的 `fetch` |
| Crossref 返回 429 | 请求过密 | 降低 `CONC` 环境变量；Crossref 友好池要求带 `mailto` |
| 产物里又出现邮箱 | 生成脚本把主页文本原样带出 | 跑 `node tools/strip_emails.mjs`，并检查是否有新字段名未被 `EMAIL_KEY` 覆盖 |
| HTML 打开后表格空白 | 数据 JSON 被破坏 | `node tools/verify_html.mjs reports/*.html` 定位 |

## 四、扩展方向

- **增加学校**：见 [CONTRIBUTING.md](../CONTRIBUTING.md) 第二节；
- **增加期刊层级**：改 `tools/classify.mjs` 的 venue 分层表（S/A/B）；
- **增加方向标签**：改 `tools/curate.mjs` 顶部的 `GROUPS` 数组（顺序=匹配优先级，多标签）；
- **增加分析维度**：在 `tools/score.mjs` 里补充指标，并在 `tools/rank_final.mjs` 的权重表里登记。

---

## 五、红线（务必遵守）

1. **不采集邮箱**，不放任何联系方式字段；
2. **不编造数据**——核实不了就填 `null`，绝不推测；
3. **不使用登录墙 / 付费墙 / 私人渠道的数据**；
4. **不做个人评价**——产物中不得出现"水平差""不推荐""避雷"等评价性表述；
5. **收到更正或删除请求，7 个工作日内处理**，无需对方提供证件。

完整合规要求见 [DISCLAIMER.md](../DISCLAIMER.md)。
