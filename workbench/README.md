# 跨专业导师调查工作台

一个在本机运行的导师调查工作台。主页提供两条以选择为主的路径：输入姓名并在同名候选中核对学校、院系和方向；或选择一级学科直接查看名单，再按高校和方向缩小范围。选定身份后，在同一份档案中查看公开来源、论文线索、关系分析与读研体验参考分，登记补充证据与人工核查状态，再导出 Markdown 调查记录。

工作台默认只展示 **38 个工学一级学科**（2022 年目录 08 门类）；另有 79 个非工科学科的数据保留在库中、保留原 ID，可用界面「显示非工科」开关查看。**不评价学术水平与指导质量**，但会给出证据可追溯的学生向参考分（口径见 [DISCLAIMER.md](../DISCLAIMER.md) 第四节之二）。

**东北大学按研究所各建一个 `SPECS` 条目，而不是只挂总览页**，有两个实证理由：① 总览页只列 101 人，而各研究所自己的名录页合计 123 人（电气自动化研究所一所就有 33 人），逐所更全；② 逐所建模让每条记录带上**所属研究所**，院系字段不再是笼统的学院名。实测各单位之间**重名 0 人**。

**东南大学这份来源的做法值得单独记一笔**：四个候选 `list.htm` 在服务端**都是空壳**（只有 `div.loading` 与空的 `ul.cols_list`，普通 GET 拿不到任何姓名），名单由模板脚本异步取回。真正的数据源是站内教师查询服务 `_wp3services/generalQuery`（响应体是 JSON，但 `Content-Type` 写的是 `text/html`）。该服务的 `exField2` 装教师电话、`exField3` 装外部网址，模块用 `returnInfos` **字段白名单不申请**这两个字段，因此**联系方式在取数层就不存在**，而不是靠事后过滤。实测复核：响应体 17,438 字符内 0 个邮箱、0 个电话。这套 WebPlus 结构（`wp_paging`、`/_wp3services/generalQuery`）在其它高校也常见，遇到"页面是壳"时可照此排查。

> **该来源的两处缺口（如实记录）**：① 服务自报 `total=114`，但**任何查询都只返回同一批 100 条**（`pageIndex=2` 为 0；`rows=100` 分 87+13；换 6 种排序与 `exField1`／`post` 各类切片都只是这 100 人的子集），因此**另外 14 条取不到**，该缺口已写进每条记录的备注；② 服务只给到**学院一级**（`department=自动化学院`），没有系或研究所，故这 95 行的院系全是学院名，不代表学院里某个具体的系。

**刻意排除的三类**：① 三校的「按职称」名录与「博导／硕导」名录都是**同一批人的另一种切法或子集**（浙大的院士／国家级人才栏目经核实是教师名录的严格子集），合并只会给同一个人造出重复行；② 学院下属部分研究所（如电工电子、微纳传感）与电子信息、电气工程更相关，未纳入 0811；③ 东南大学 100 条中有 5 条是院办、教学秘书、研究生秘书、辅导员且不带任何导师标签，按"跳过行政单位"整条排除。

三校名录都不写研究方向，故 325 位方向一律为「方向待补」，职称与研究所名只作为院系分组与来源说明。

**两条口径说明（都写进了模块文档与测试）**：

## 修复：`fetch()` 用 chardet 猜测覆盖了正确编码，导致"整页 0 行"（2026-10-15）

**这是本轮最重要的发现。** `fetch()` 原先把服务端声明的编码用 chardet 的猜测覆盖掉：

```python
response.encoding = response.apparent_encoding or "utf-8"   # ← 旧写法
```

东北大学冶金学院名录声明 **UTF-8**，chardet 却猜成 **`ptcp154`**（西里尔文），于是整页变乱码、中文姓名全部匹配失败——解析器在**明明有 230 人**的页面上返回 **0 行**。第一次合并时 `added: 0` 就是这个原因，不是数据没有。

修法：优先信任真实声明；声明缺失时依次试 UTF-8 → GB18030；若声明解出的文本里没有任何汉字而字节里确实含汉字，则回退重解。补了 4 个离线回归用例（`FetchDecodingTests`：声明 UTF-8 被信任、错误声明回退、GBK 页面、纯 ASCII 不受影响）。

**教训**：**"解析出 0 行"未必是页面没数据，也可能是解码错了。** 判断一个新来源能否使用，先看它解码后的中文是否正常，再看行数。

## 网络抖动与可达性判断（重要，遇到"打不开"先读这一节）

本机通过 **Clash Verge（`verge-mihomo`，TUN 模式）** 联网，它创建一个名为 `Meta` 的虚拟网卡（跃点 0，优先于 WLAN），所有域名由它做 fake-IP 解析到 `198.18.0.0/15` 网段再按规则转发。实测该链路**会整段失效**：

| 观测 | 结果 |
|:--|:--|
| 同一批 `.edu.cn` 主机连续探测 | 曾出现 **9 个全部 SSLError**，几分钟后同样主机 **5/6 返回 200**，之后又出现**连续 4 轮 0/4 全失败** |
| 同时刻对照组 | `www.baidu.com` 一度可正常返回 737 KB，说明"外网全断"与"仅 `.edu.cn` 不通"两种情况都出现过 |
| 走显式代理 `127.0.0.1:7897` | 与默认路径同样的失败模式，说明问题在代理的**规则/节点**，不在站点 |
| 用公共 DNS（223.5.5.5 / 119.29.29.29 / 1.1.1.1）绕开 fake-IP | 本地 DNS 被劫持，**公共解析器无应答**，无法从应用层绕开 |
| 最后阶段 | 连 `www.baidu.com` 也超时，隧道整体失效 |

**因此有三条操作纪律**：

1. **单次探测失败不能作为"站点不可达"的证据。** 判死一个来源前，至少重试 3 次（采集器自带的 `fetch(url, attempts=3)` 会退避重试），并同时试 `https` 与 `http`、`.edu.cn` 与 `.cn` 两种域名写法。本仓库文档里此前把地质学科的原因写成"TLS 握手直接失败"，按这套标准应当更谨慎地表述。
2. **提交前的验收必须在网络可用时跑。** 采集器 `--dry-run` 与 `--enrich` 都依赖联网；网络抖动期间跑出的 `failures` 列表**不代表来源有问题**，恢复后应重跑再判断。
3. **已抓取的离线快照不受影响。** `workbench/tests/fixtures/` 下 28 份快照与全部契约测试**完全离线**，网络不可用时仍可运行 `python -m unittest discover -s workbench/tests`，这是本项目"可复现"的一部分。

## 选择调查项目

选定导师后，默认打开“调查概览”。勾选项目并点击“开始调查”，整理身份来源、论文候选年份、关系证据和匹配的旧档案；这四项离线运行，不自动改变人工核查状态。默认汇总本地最多 12 条论文和用户选定的 OpenAlex 作品样本，不代表全部成果。最近一次结果保存在本机，可随调查记录导出；来源、论文或关联档案变化后会提示重新整理。再次运行会替换上一次任务摘要，保留人工备注与证据。

可另选“DOI 元数据核对”，从已有候选中每次选择最多 3 篇，通过 [Crossref REST API](https://www.crossref.org/documentation/retrieve-metadata/rest-api/) 查询登记标题、作者、年份和刊会。该功能需要联网，只发送 DOI，不需要 API key；接口限流、无记录和查询成功分别展示。找到登记记录不表示已确认导师署名或论文内容，未返回记录也不能据此判断论文不存在。

“接下来核查什么”按八项人工核查状态列出待办，默认展开前三项，其余可点选展开。每项提供资料查看和“登记证据”入口，后者会预选对应类别；已人工核查、不适用和待办分别计数。新增来源不会自动完成核查。导出的 Markdown 同步包含当前后续核查清单。

旧调查档案默认读取仓库同级 `academic-investigations` 文件夹，也可在启动前用 `$env:MENTOR_ARCHIVE_DIR='你的旧调查目录'` 指定。当前仅对已登记的姓名与机构组合关联固定档案路径，提取教育、工作、研究领域、历史产出及共同作者摘录；不继承个人评价、联系方式或旧评分。目录不存在时正常显示未找到匹配档案，不影响其他模块。履历、招生和项目检索链接用于打开搜索页面，系统不声称已自动访问或核实这些网页。

## 导入与证据

不必准备文件也能补资料：左侧“没找到？添加导师”可填写姓名，选择一级学科，选择或输入学校。院系、方向和主页可稍后补齐；没有选资料夹时会保存到“我的导师”。当前资料夹会在浏览器中记住。姓名、学校、院系和主页都相同的重复记录会提示已有资料。

“论文”页可手动添加标题、DOI 或原文链接，年份选填。保存后会进入资料汇总和导出；带 DOI 的论文可勾选联网核对。手动论文的作者归属保持待核对；误填的论文可移除。OpenAlex 查询失败不影响手动添加，更新论文时也会保留查询期间新写的笔记。

CSV 至少包含 `姓名,机构`；推荐再加 `院系,学科,研究方向,简介,主页`。英文键名也可使用 `name,institution,department,discipline,interests,summary,homepage`。参见 [模板](examples/import_template.csv)。JSON 可直接使用对象数组，也可使用 `{ "profiles": [...] }`；每条还能带 `sources: [{"url":"https://...", "title":"...", "claim":"..."}]`。单次至多 5000 条、10 MB。无姓名或机构的记录跳过；仅姓名、机构、院系、主页四项都相同的记录自动去重，避免误合并同名教师。

主页链接和来源声明由导入者提供，系统仅检查 URL 格式，不自动确认页面内容。来源状态默认“待人工核查”。标成“已人工核查”只记录当前用户的动作，不能代替来源时效、同名消歧、招生简章或与导师本人沟通。外部资料的 `notes` 字段不会变成用户的核查备注；用户备注须在工作台内填写。导入的文本会屏蔽邮箱地址。

可直接导入仓库现有 `data/processed/mentor_ranked.json` 来复用旧 IC 专题的姓名、单位、方向和主页线索。导入时会把旧方向代码转换为中文学科描述，但**不会**导入旧综合分、梯队、诚信推断或排名。这些历史输出的 DOI 接口限流与评价方法尚需单独复核。

## 检索机制和复现

“AI 语义检索”使用 [BAAI/bge-small-zh-v1.5](https://huggingface.co/BAAI/bge-small-zh-v1.5) 的本地 ONNX 向量，经 [FastEmbed](https://github.com/qdrant/fastembed) 生成查询与资料向量，以余弦相似度排序，资料向量缓存在 `.workbench-data/indexes/`。它与按双字重合度排序的关键词基线并列，方便核查 AI 是否真正有帮助。语义分数没有跨查询可比性，也不是可信度、适配度或优劣分。该中文模型对英语等语言以及专业术语的表现尚未系统验证。

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s workbench\tests -v
node --test workbench\tests\test_ui_races.cjs workbench\tests\test_research_ui.cjs
.\.venv\Scripts\python.exe -m workbench.evaluate_pilot
```

当前有 72 项 Python 行为测试，以及 11 项使用 Node 内置测试器的前端异步请求测试（需 Node.js 18+）。覆盖个人页解析、身份来源约束、年度招生记录匹配、失败更新保留资料，以及快速切换学科、高校、方向、导师时旧结果不得覆盖当前选择；它们不代替浏览器交互验收。

8 条来源试点上的 8 个事先写定查询：语义检索和关键词基线都取得 Top-1 `7/8`、Top-3 `8/8`。这只是小样本工程冒烟检查，不能证明语义检索优于关键词，更不能证明学生选导师的实际效果。公开可复现的查询与期望项见 `evaluate_pilot.py`；后续需要独立标注、多学校真实资料和学生任务测试。
