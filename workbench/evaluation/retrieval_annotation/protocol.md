# 独立检索评测：人工标注协议（0–3 级相关性）

> 状态：**待标注**。仓库目前只有规则生成的弱监督评测（226 查询，见
> `workbench/reference/eval/retrieval.json`）。它衡量的是「与规则的一致性」，
> **不是真实用户准确率**。本协议用于建立真正独立的人工评测集；在收集到足够标注前，
> 不得把任何弱监督指标写成人工评测结果。

## 一、为什么要另做一套

| 现有评测 | 本协议 |
|:--|:--|
| 查询由学科/方向/术语表规则生成 | 查询来自真实学生提问或任务描述 |
| 相关性由规则推导 | 由**不知道系统方法**的人逐条打分 |
| 指标可复现但含规则偏置 | 指标可复现且反映真实需求 |

## 二、查询集设计（目标 60–80 条）

按类别各 10–15 条，全部记录在 `annotation-template.csv`：

1. **真实研究兴趣描述**：如「想研究电池快充时界面怎么退化」。
2. **中文专业术语**：如「硅光调制器」。
3. **英文缩写**：`VLSI`、`MEMS`、`EDA`、`RISC-V`、`FPGA`。
4. **中英混合**：如「用 Transformer 做芯片布局」。
5. **跨学科**：如「AI 用于材料发现」。
6. **完全无关的负例**：如「红烧肉怎么做」。
7. **身份歧义查询**：如「清华 王伟 教授」——考察系统是否会先做同名核对。

## 三、相关性等级

| 等级 | 含义 |
|--:|:--|
| 3 | 研究方向直接对应，导师能指导学生做这件事 |
| 2 | 方向相关，但不是核心 |
| 1 | 同学科/同院系，方向只沾边 |
| 0 | 不相关，或证据不足以判断相关性 |

- 只依据**公开资料**（档案中的研究方向、论文、院系）判断，不使用个人印象。
- 不确定写 0，并在 `notes` 说明「证据不足」；不要把不确定标成 2/3。

## 四、标注流程

1. 由项目维护者把查询按类别补进模板（当前模板只有示例行，**不带任何标签**）。
2. 候选池：对每条查询，从「关键词 / BM25 / 向量 / 混合」四种方法各取前 10 条，
   合并去重后**按固定种子随机排序**，隐藏来源方法——标注者看不到是哪种方法召回的。
3. 两位标注者独立打分（0–3）。`reviewer` 与 `reviewed_at` 必填。
4. 分歧处理：分数差 ≥2 的条目由第三人或两人协商确定，`notes` 记录双方原始分与理由。
5. 汇总后在本地计算 Recall@K / MRR / nDCG@K / 拒绝错误查询的比例 / 延迟；
   **仓库只提交汇总指标与协议，不提交标注者姓名**。

## 五、指标口径（标注完成后）

- 相关性按 0–3 折算增益（`2^rel - 1`）计算 nDCG@K；
- Recall@K 以 rel ≥ 2 为「相关」；另报 rel ≥ 1 的宽松口径；
- 负例查询（类别 6）单独统计「是否返回空/低置信」；
- 延迟分三段报告：模型冷启动、索引构建、单次查询（热）；
- 同时报告每种方法的 `fallback` 次数（模型不可用时回落到 BM25）。

## 六、字段（`annotation-template.csv`）

| 列 | 说明 |
|:--|:--|
| `query_id` | 查询编号 |
| `category` | 上述 7 类之一 |
| `query` | 查询原文 |
| `candidate_id` | 候选导师记录 id（用于回查档案） |
| `candidate_name` / `institution` / `direction` | 候选的基本信息（供判断） |
| `relevance` | **待填**：0/1/2/3 |
| `reviewer` / `reviewed_at` / `notes` | 标注者、日期、依据 |

## 七、禁止事项

- 不得用模型自动生成 `relevance` 后冒充人工标注。
- 不得只标注「系统排在前面的结果」——候选池必须包含各方法的并集。
- 不得因为结果不好看而剔除查询；查询集一旦开始标注不得增删。
- 标注不足（<40 条查询或缺少负例）时，只报告「待完成」。
