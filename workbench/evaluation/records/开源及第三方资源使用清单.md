## 五之二、Academic Detective「学术侦探」方法借鉴逐条对照

学术侦探给出了**七步调查框架**（`SKILL.md`）与**三个执行层次**。下表逐条说明本项目**用了什么、用在哪里、以及哪些没有采用**，避免只写"参考了框架"这类笼统表述。

| 对方的方法 | 是否采用 | 本项目落在哪里 | 说明 |
|:--|:--|:--|:--|
| **Step 1 基本档案**：从官方主页建立身份与任职时间线，区分"自称"与"核实" | ✅ 采用 | `workbench/catalog.py` 的 `discipline_assignments` / `sources`；`workbench/public_research.py` 的来源登记与 `with_catalog_records()` | 官方名录、个人主页、招生目录分别标注来源类别；未获二次来源确认的一律保持"待人工核查" |
| **Step 2 产出核实**（声称 vs 实际），并用 **DOI 反查**锚定真实作者档案 | ✅ 采用 | `workbench/openalex.py`（作者候选）、`workbench/investigation.py`（Crossref DOI 元数据核对，每次最多 3 篇） | **DOI 反查消歧**这一条直接对应我们的做法：先有 DOI 再核对标题/作者/年份/刊会，不用姓名直接绑定 |
| **Step 4 关系网络**：合作者图谱、团队绑定程度 | ✅ 采用并扩展 | `workbench/relations.py`（L1 明确师承 / L2 共同指导 / L3 同门 / L4 共同署名） | 对方以合作者图谱为主；本项目按**证据强度分四级**并把"是否可视为师承"写成字段，共同署名不推定为师承 |
| **Step 5a 异常检测 C01–C07**：产出量、期刊集中度、署名结构等 | ✅ **直接调用其模块** | `tools/skill_heuristics.py` → 导入 `analysis.common_heuristics.CommonHeuristicsClassifier` | 这是唯一**按原样调用对方代码**的地方，通过 `ACADEMIC_SKILL_SCRIPTS` 指向其安装位置，未复制进本仓库；未设置时该步骤安全跳过 |
| **Step 6 多源验证**：每个主要发现至少 2 个独立信源（独立 = 非同一来源衍生） | ✅ 采用 | 本仓库维护指南的红线；`workbench/reference/*.json` 逐批核对记录；16 项公开前审计 | 项目早期曾因只信采集过程而出错，此后把"产出侧独立复核"写成硬规则 |
| **多源口径矛盾的处理**：对比同一学者的多个官方来源（如官网"论文 70 余篇" vs "30 余篇"），记录差异而不择一 | ✅ 采用 | 来源状态字段 + 不自动认证；`DISCLAIMER.md` 与各批核对记录中的口径说明 | 例如本清单与技术报告中均写明"公开来源试点不等于完整调查""有页面不等于论文已补齐" |
| **三个执行层次（L1 文献计量 / L2 深度分析 / L3 关系口碑）**，按数据可得性分层、明示未完成部分 | ✅ 采用其**分层与明示**思想 | `workbench/student_score.py` 的"无公开证据"维度 + 依据覆盖比例；`workbench/README.md` 逐批写明遗留项 | 不把"没数据"当作结论，缺失即明确写缺失 |
| **Step 7 报告生成**（Markdown → 报告 + 图表） | ✅ 采用思路，自行实现 | `workbench/catalog.py` 的 `report_markdown()` 导出逐人 Markdown 调查记录（含后续核查清单） | 自行实现，未使用其报告与图表代码 |
| Step 0 案件注册（SQLite `case.db` + `.state.json` + 目录结构） | ⚠️ 仅采用思路 | `workbench/core.py` + `workbench/investigation.py` 的本机 JSON 存储（`.workbench-data/`），无 SQLite | 改为单文件 JSON，便于用户自行备份与查看；不引入其数据库结构 |
| Step 3 六维质量评分 / `paper_quality_rubric` / `hybrid_scorer` | ❌ **未采用** | —— | 需要论文 PDF 全文，且输出的是**学术质量评分**。本项目定位为学生向参考分，明确不评价学术水平，故不采用 |
| 数据造假指纹检测 / `stats_reverse_engineer` / `image_metadata_extractor` | ❌ **未采用** | —— | 属学术不端取证，超出本作品范围，且需 PDF 与图像原始数据 |
| 风格计量学 / `stylometry_profiler`、引用星座图 / `citation_constellation` | ❌ **未采用** | —— | 同上，需全文与完整引用数据 |
| 学生口碑抓取（研学网评价表、小红书、RMP）与 `review_aggregator` | ❌ **未采用** | —— | 本项目**不采集主观口碑**：该类来源无法追溯、且指向具体个人，与"证据可追溯"的定位冲突 |
| 零宽水印嵌入 / `watermark`（`core/watermark.py`） | ❌ **未采用** | —— | 属其分发与防匿名商用的手段，与本作品无关；本项目也不需要该机制 |

**一句话总结**：本项目采用了学术侦探的 **Step 1 / 2 / 4 / 5a / 6 / 7** 六个步骤的方法思路与**三层数据可得性分层**，其中 **Step 5a 的 C01–C07 异常规则是按原样调用其模块**；**未采用**其 Step 3 六维质量评分、数据造假取证、风格计量、引用星座图、学生口碑抓取与零宽水印。所有采用的部分，本仓库均为自行实现（除 5a 为原样调用），其代码未纳入本仓库。
