# 真实用户任务验证：实验协议（当前状态：未招募用户）

> 状态：**协议与记录模板已备，尚未开展用户研究**。
> 因此技术报告与 README **不得**声称「提高效率」「改善决策」，也不得报告任何
> 完成时间、成功率或主观评分。

## 一、目的

验证工作台在真实导师调查任务中的可用性：能否找到人、能否区分同名、能否追溯证据、
能否留下可复查的记录。**不是**验证导师好坏，也不是评估模型准确率。

## 二、任务设计（6 项，见 `tasks.csv`）

| 编号 | 任务 | 成功判据（客观） |
|:--|:--|:--|
| T1 | 在指定一级学科中找到 3 位导师并打开档案 | 3 份档案均来自该学科，且能说出所属机构 |
| T2 | 在 2 位同名导师中确认哪一位是目标 | 选中正确记录，并指出用于区分的证据字段 |
| T3 | 追溯某位导师研究方向的来源 | 至少指出 1 条来源 URL 与页面上的原文依据 |
| T4 | 核实某年招生信息 | 找到招生年份/公告并说明是否适用于目标年份 |
| T5 | 查看论文候选并判断归属 | 能指出「候选/已核对」的区别，不把候选当事实 |
| T6 | 形成一份可导出的调查记录 | 导出 Markdown，包含来源、核查状态与备注 |

## 三、流程

1. 招募 5–8 名工科在读学生（不同学科背景），签署知情说明（仅记录任务数据）。
2. 每人独立完成 6 项任务；使用本机工作台；允许使用浏览器查证公开页面。
3. 记录：开始/结束时间、是否成功、错误类型、是否需要提示、主观反馈（1–5 分）。
4. 结束后做 5 分钟半结构化访谈，重点问「哪里让你不确定」「你最不信哪一块」。
5. 汇总时不报告个人身份，只报告任务级统计与匿名引言。

## 四、错误类型编码

| 代码 | 含义 |
|:--|:--|
| `wrong_person` | 同名/错人 |
| `wrong_source` | 来源点错或未核对 |
| `no_evidence` | 找到了页面但没记录依据 |
| `misread_field` | 把候选/推断当成事实 |
| `gave_up` | 超时或放弃 |
| `other` | 其他（备注说明） |

## 五、指标（仅在真实完成后报告）

- 任务成功率（按任务分别报告，不合并成一个总分）；
- 中位完成时间与四分位区间；
- 每类错误出现次数；
- 主观易用性中位数（1–5）与代表性反馈；
- **样本量小**（5–8 人）时只作方向性参考，不做统计显著性宣称。
